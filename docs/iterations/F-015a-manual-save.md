## 继承约束检查

- F-002：正文仍以用户磁盘文件为唯一真源；只由用户手动保存写回已授权的当前文件，离线可用。不实现自动保存、另存为、未命名文档、恢复或联网操作。当前沿用 1 MiB 验证边界。
- 中文与外观：保存入口、状态、错误采用中文并继承系统/浅深主题；状态不只依赖颜色表达。
- 命令与键盘：保存按钮、菜单、命令面板与 `⌘S` 复用统一命令及当前文档上下文。无活动文档、无变化或确认期间不可误写；本轮无拖放操作。
- 安全与日志：前端不能提供目标路径；后台校验授权、身份、基线和大小。Markdown 只作数据，不执行脚本。错误与日志不泄漏正文或原始系统路径。

## 1. 功能说明

- 当前已打开文档可手动保存；明确显示未保存、保存中、已保存、保存失败/冲突或保存结果未确认。
- 保存捕获内容版本快照；保存期间允许继续编辑。成功只更新该快照对应的磁盘基线，不重置当前正文、撤销、选区或滚动。后续修改仍为未保存。
- 同一文档写入串行，避免重复请求并发替换；不同文档写入有界。不把标签切换或失焦当成保存。
- 保存前核对磁盘内容与已读基线；发现外部修改、删除、替换或授权变化就拒绝覆盖，保留内存修改。完整冲突解决由 F-028 承接。
- 关闭、清空、重新读取、刷新与退出先等待已开始写入收尾，再按当前状态判断是否需要放弃确认；不因关闭而新发保存。后台也须保护写入与生命周期，不能仅依赖前端 RPC Promise。
- BOM、未修改的混合换行、孤立 CR、末尾换行按内存原文写入，不在保存时格式化或转码。

## 2. 最小技术方案

- `saveDocument` 请求绑定 handle、documentId、expectedRevision/hash、bufferRevision、text 与 requestId；严格运行时验证。成功回执返回提交快照及对应 bufferRevision，不能用旧回执清除较新修改。
- 后台从已授权文件及父目录操作：同目录随机独占临时文件、完整写入、复制必要元数据、强同步、提交前重新核对身份/内容、安全原子替换、目录同步。不得回退为截断原文件写入。
- macOS 原生系统 fd 接口 `fcopyfile`、`F_FULLFSYNC` 和目录 fd 定位已通过隔离 PoC；用户确认生产采用预编译 Node-API 原生模块，固定受限接口，在后台 worker 执行同步文件操作，避免阻塞主进程。产品不接入实验性 Bun FFI 或运行时 C 编译。需验证本地构建与 Electrobun 产物中模块加载，不修改原生窗口实现。
- rename 之前失败保持原文件；rename 之后持久化/授权更新失败只能报告结果未确认，保留内存与未确认状态，不盲目回滚或无限重试。原子可见性不等于掉电持久性。
- 普通文件路径/哈希复核不等于操作系统 compare-and-swap；对于最终校验至替换之间的非协作外部写入、特殊卷与元数据边界须提供实际证据，无法满足已确认安全要求时先说明并取得用户决策，不默默削弱保证。
- 临时安全边界与完整保存状态机的延期范围根据 PoC 明确记录；本轮不以缺少正式模式、自动保存、watcher 或跨模式消费者为由宣称父功能完整实现。

## 3. 最小 happy path 与风险验证

1. 临时 Markdown 样本编辑后按 `⌘S`，磁盘读回等于提交原文，状态变已保存；再次编辑变未保存，关闭未修改标签不再提示放弃。
2. BOM、混合 LF/CRLF、孤立 CR 和无末尾换行样本保存后逐字节验证；连续保存与重新读取保持文档身份。
3. 用可控延迟验证保存期间新编辑不会被旧回执清除；非活动文档回执不能修改活动文档。
4. 外部编辑、文件/父目录替换、只读权限、临时写入/同步/替换失败时不丢内存或覆盖已检测外部内容；替换后失败单独验证未确认语义。
5. 保存与关闭、刷新、退出及 RPC 失败的交叉由后台屏障测试覆盖；人工验证正常保存、关闭和未保存提示。

## 5. 人工验收步骤

先运行 `bun scripts/create-f015-fixtures.ts` 创建五个一次性样本；**保存会真实改写文件，不要使用重要文档验收**。本轮不使用 F-012a 的“磁盘保持不变”作为保存成功标准。

1. 打开 `01-save.md`，追加 `SAVE_OK`，按 `⌘S`；等待已保存后用外部工具读回，确认内容已写入。再次编辑应重新显示未保存；保存后关闭该标签不应提示放弃。
2. 打开另一篇样本，分别修改两个标签；用按钮、菜单或命令面板保存当前文档，另一篇的修改仍保留。保存不重置撤销、选区或滚动；不要把切换标签当成保存。
3. 打开 `02-mixed.markdown`，只改一处文字并保存；检查 BOM、LF/CRLF、孤立 CR 和末尾换行诊断未发生无关归一化，重新读取后内容与保存结果一致。逐字节保真另由自动测试验证。
4. 打开 `03-conflict.md` 后在 App 内修改，再用外部编辑器改变磁盘文件；尝试保存，应提示冲突/文件变化并保留内存与外部版本，不静默覆盖。完整冲突合并不在本轮。
5. 编辑 `04-readonly.md` 后保存，应失败且内存修改保留；`05-empty.md` 输入后可正常保存。保存后再次编辑，分别取消关闭/退出确认，确认修改仍在；明确放弃才关闭。

人工结论等待用户；若遇“保存结果未确认”，先保留所需内存内容并核对磁盘，按提示重新读取或重新选择，不反复点击保存。构造 RPC 丢失和提交后失败的场景由受控自动验证覆盖，不要求人工故障注入。
