## 1. 功能说明

### 1.1 本轮范围

- 沿用严格有效 UTF-8 与可选文件开头 UTF-8 BOM（字节顺序标记）。成功读取的快照保持原始字符序列，BOM 不被静默剥离，LF、CRLF 与孤立 CR 均不归一化。
- 与当前文档快照共同提供编码信息、开头 BOM、LF/CRLF 计数及混合情况、主换行风格、孤立 CR 计数、末尾换行信息。在诊断区查看即可，无需理解不可见字符。
- CRLF 作为一个序列统计，不能同时算作 LF 或孤立 CR。LF 与 CRLF 都出现时标为混合；仅其中一种出现时标为对应风格。两者均无时显示“无 LF/CRLF”；计数相等且都非零时主风格显示“并列”，不擅选 LF 或 CRLF。孤立 CR 单独显示，不假定它是 LF，也不据此制定将来的编辑转换策略。
- 末尾明确区分 LF、CRLF、孤立 CR 与无换行；空文件、仅 BOM 文件均为无换行。这里仅描述文件原始结尾，不代表新增行或保存策略。
- 无效 UTF-8 安全拒绝，保留原文件列表与正文，沿用读取失败时必要的旧快照提示；中文错误说明需由外部工具转换，不猜测传统编码，不自动转换。

### 1.2 范围外与状态变化

本轮不提供编辑、保存、换行转换、编码选择、格式化、正式阅读模式、大文件解限或会话恢复。W-24 中局部编辑保留未触及范围和新增行随光标上下文的行为归 F-012 / OBL-062；保存保留 BOM、换行及末尾属性归 F-015 / OBL-063。

## 2. 最小技术方案

### 2.1 已检查的现有链路

- Bun 文档读取使用 `new TextDecoder("utf-8", { fatal: true, ignoreBOM: true })`，其中 `ignoreBOM: true` 当前使 BOM 留在结果文本中；原始字节计算 hash、byteLength 和内容 revision。
- `shared/documents.ts` 的 `DocumentSnapshot` 已携带 text、hash、byteLength、documentId 和 revision。
- `client/documents.ts` 的响应校验已核对协议、请求、枚举、大小与 UTF-8 重新编码字节数；新方案不通过剥离 BOM 或归一化换行破坏该文本/字节对应关系。

### 2.2 本轮最小改动提案

1. 在严格解码成功后对现有文本做一次 O(n) 轻量扫描，以固定大小计数/标记产生元信息；不 split 全文、不创建另一份规范化正文。开头 BOM 依据原始字节识别，正文中的 U+FEFF 不当作文件 BOM。
2. 在共享快照契约中加入只读保真元信息，随同同一 documentId/revision/hash 原子返回与应用，不维护独立可漂移状态。具体字段名在实现时保持小而明确，不冻结未来保存 schema。
3. 更新客户端运行时校验和测试，验证计数安全整数、合法枚举、计数范围和组合一致性；现有全文/字节验证继续保留，不额外制造多个全文副本。继续使用当前受控读取协议，不引入新 RPC 命令或依赖。
4. 诊断折叠区显示当前已提交快照的元信息，切换与重读随快照同步；失败、取消、过期响应不提交错误候选。调整无效 UTF-8 中文提示，说明外部转换路径。
5. 记录实际测试/构建与必要观察，不设性能数值门槛。实现后如重新打包，按仓库规则递增 alpha 并核对产物版本。
