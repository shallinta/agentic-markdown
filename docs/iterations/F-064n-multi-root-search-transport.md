# F-064n 多根正文查询传输

## 范围

在普通窗口的现有正文查询 RPC 增加多根操作。调用方提交一至十六个不同的根句柄和各自的扫描代，获得一份聚合覆盖与文档配对。根选择、分组和定位界面由后续迭代接入。

## 最小实现

1. 共享校验明确区分单根、多根和取消请求。多根只接收有界且无重复的根句柄列表，每项包含扫描代。结果回显同一顺序、同一版本的根列表，并校验覆盖范围和打开文档配对结构。
2. 多根走 F-064m 的聚合查询，沿用普通窗口就绪、同一在途槽、取消、退出等待和结果未知处理。旧单根、定位准备和隔离实验入口沿用原语义。
3. 目录路径、根别名及未保存正文均不进入请求。范围和版本以 Bun 的授权及扫描记录为准。

## 最小验收

- 定向覆盖请求形状、重复根、过多根、响应根乱序或代数变化、取消、与单根及定位准备互斥，以及未知结果优先级。
- 通过实际原生索引从两个合成授权根经 RPC 得到同一回执。包内复跑，真实 WK 窗口回归单根查询、定位和正常退出。

## 继承约束检查

- F-002 沿用本地授权、索引和传输。离线留最终人工。
- 中文与外观沿用已有错误和主题，界面接入后再验多根展示。
- 命令与键盘沿用现有单根入口。
- 安全与日志方面，Bun 独立核对根及其扫描代，搜索内容和物理路径不写入日志。

## 实际验收

- macOS arm64 unsigned canary `0.1.0-alpha.201`，包标识 `1y5j9obcissbk`。源码和包内 Bun 1.4.0 配合正式原生资源各复跑 15 项通过，6 项条件外层跳过由隔离子进程执行。包内单独复跑多根场景，38 条断言通过。
- 实际原生模块经 Bun RPC 处理器查询两份授权根，验证回显根顺序、文件命中 UTF-16 区间、第二根打开文档配对以及单次会话。定向覆盖无效别名、重复根、过期扫描代、回执乱序、在途槽互斥、取消及未知结果优先级。规格与规范独立复核无阻断。
- 真实 WK 窗口用既有单根入口查询「研发笔记.md」并定位 `[7,11)`，正常退出。夹具 SHA 不变，窗口和包测的查询临时目录均为空。退出时观察到一条系统 IMK 日志，进程正常结束。多根传输本轮由包内 Bun 验证，窗口多根入口留下一片。
- 源码全量 1855 项通过、8 项条件跳过、1 项失败，共 38,886 断言。唯一失败为既有 FINAL-ISSUE-002 长空白用例超时。类型、Lint、文档、义务登记、锁文件和差异检查通过。
