# F-037v Markdown 内容块锚点实验

## 功能说明

验证正文前面插入其他段落后，仍可按原内容定位未变化的 Markdown 块。本轮提供内部算法和本地夹具验证，为 R-15 跨重启滚动位置恢复准备锚点。

## 最小方案

- 复用编辑模式的 canonical Markdown 解析结果，从顶层内容块提取原文 UTF-16 区间。列表、引用和围栏各作为一个块，引用定义不参与定位。块类型、零字节和块原文 UTF-8 字节构成 SHA-256 摘要的输入。
- 原文摘要相同时，用块摘要和同摘要块的出现序号恢复。正文变化时，只有目标摘要在新旧正文中均唯一才定位。目标缺失或无法区分重复块时，交给后续逐级回退处理。
- 沿用 1 MiB 文档边界。普通窗口与持久检查点的接入留给后续切片。

## 最小验收

- 在包含 BOM、CRLF 和 emoji 的合成文档中采集锚点，分别用原文、前插新块、重复或删除目标块的版本定位，核对返回的区间及原文。
- 运行 1 MiB 长行和密集多块夹具，核对容量及摘要规则。用同包普通窗口回归标签重新授权、恢复和正常退出。

## 继承约束检查

- F-002 使用本地合成文档，离线留集中验收。
- 中文与外观沿用普通窗口，实验通过包内 Bun 执行。
- 命令与键盘回归原生重选和退出。
- 安全与日志核对有界解析、原文区间及摘要，实验输出用合成输入验证。

## 验收记录

- 包内 Bun 执行仓库实验。固定摘要、BOM、CRLF、emoji、半开区间、前插、重复、删除、精确 1 MiB 和 4096 块夹具通过。完整套件 2333 项通过、55 项跳过、0 失败，共 47082 条断言。1 MiB 和密集块的单次用例耗时约 150 和 120 毫秒，包含测试断言。类型、Lint、文档、锁文件及差异检查通过。
- 独立源码复核发现旧文的重复块只剩一份时可能误定位。已要求新旧正文均唯一，复核复跑 52 项通过。文档变化时，摘要只确认块原文与类型相符。
