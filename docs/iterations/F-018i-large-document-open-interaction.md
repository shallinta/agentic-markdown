## 最小技术方案

1. 先建立同机真实磁盘样本与普通小文件对照，记录原始大小和结构；隔离测试数据，不覆盖用户正文。用户在选择器停留的时间与选择返回后的应用处理时间分开。
2. 在当前真实打开路径用公开可观测点区分读取、传输、编辑状态初始化、View 初始化、首次可用交互与语法就绪。跨进程时钟不可直接相减；嵌套区间不重复相加，无法准确分离的阶段记未知。工具调用、可访问性树和截图超时不是 App 响应时间。
3. 先测量、定位，再在当前消费者范围内选择最小保护并以同口径复测；优先复用现有公开 API 和固定 Worker。不默认把所有文档转后台解析，不更改已保留的 `wait` 策略，不放宽 1 MiB、Markdown 语义、软换行、原文/保存与历史边界。
4. 若公开接口无法安全解决、需要新关键策略或产品行为变化，先补本文件并重新取得用户确认；没有安全有效改进时如实报告，不以降低语义、隐藏活动内容或安全降级制造性能收益。样本规模及实测数值不是预先冻结的门禁。

已知代码接点仅作实施导航：`documents.ts` 的 `load(select)` 现有计时从调用 `selectDocument` 前开始，包含用户选择器停留，不能当磁盘耗时；响应后同步 `createRawEditorState`，`memory-editor.tsx` 在 `useLayoutEffect` 创建 `EditorView`。拟按这些边界补可观测分段，不预判任何一段是瓶颈。

现有 `viewCreateMs` 不包含 State 创建，responsive 探针使用合成传输，均不能替代真实磁盘首次打开。后台已有64 KiB分块读取、取消、身份及UTF-8/BOM校验，本片复用而非重写读取；没有达到既有10k UTF-16单行识别条件的普通多行文档仍走同步解析。帧回调只能作为调度观察，不标为首次绘制。
