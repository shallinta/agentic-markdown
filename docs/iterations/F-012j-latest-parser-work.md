## 最小技术方案

1. 当前已具备一个运行中加一个最新待处理任务、Text/requestId 与 Worker 身份隔离、过期成功/错误拒绝及长变短时终止。缺口是运行任务过期后仍计算至结束。实施时以同机同样本同输入序列比较现有等待策略与有界取消/合并候选，区分输入同步成本、最新语法就绪等待、启动/重建成本、有效结果年龄与无效计算；既有约 433ms 等待不能全部归因于旧任务。
2. 当前 Worker 内同步 parse 到结束，不能靠取消消息抢占单次解析；公开接口候选是在合适时机 terminate 后重建并合并最新请求。以普通/密集长行、持续输入及停止输入后的收敛样本指导最小策略，不每键无条件重启，不造成持续输入饥饿，停止输入后最新文本必须最终就绪；具体参数依据当轮证据，不预设数值门槛或承诺收益。
3. 始终限制运行与待处理任务数量，拒绝过期成功/结构化错误，保持长短行往返、切标签、销毁、故障与安全源码隔离；不能为避免取消而把旧树冒充当前树。保留公开 API 和现有解析器，不搭建未来通用调度框架。
4. 对候选以相同测量口径复测，保存重复原始值和限制。没有安全有效改进则保留现状并如实报告；若关键路线或用户行为需改变，先修改本文件并重新确认。

## 最小 happy path

- 普通及密集长行连续输入后停止，原文/选区立即正确，最终树与原同步语义一致；对照最新就绪等待与输入同步成本，不把纯解析、调度等待和绘制混为一谈。
- 旧任务完成或报错、长→短→长、切标签返回、模式往返后只接受当前文本；撤销/重做、保存基线与 dirty 不受语法回执影响。
- 取消与重建可再次工作，关闭和安全源码后无过期发布。控制器/合成 View 证据与实际输入、IME 和视觉体验分别记录，无法观测项标未知。
