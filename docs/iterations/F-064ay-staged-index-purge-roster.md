## 范围

为已移入待回收位置的私有索引准备固定文件名册，供后续清理时逐个核对文件。只发布名册，保留 v3 清单、目录及全部索引文件。

## 最小实现

1. 显式内部请求提供范围键、代数及 v2 摘要。同一既有槽租约内只接受唯一的待回收目录、精确 v3 清单、稳定摘要和原生控制名册。再次核对文件身份与当前状态。
2. 在同一槽中排他发布固定的 `.reclaim-purge.json`。名册记录版本、范围键、代数、v2 与 v3 摘要、v3 清单字节的 SHA-256、目录稳定身份及按文件名排序的文件身份。仅允许已知的直接文件名，最多 128 个，名册最多 64 KiB。字段使用规范数字文本，拒绝链接、路径分隔符和额外成员。
3. 使用已有保存模块的排他发布。发布前复核原清单、文件、持有的目录描述符、租约和调用方，发布后同步目录并重新核对固定名册。结果无法确认时返回 `UNKNOWN` 并保留现场。重复请求只确认精确已有名册，重新同步而无需改写。
4. 当前只读占用统计继续计入索引、原清单和通过核对的名册，名册字节单列为 `purgeBytes`。异常名册拒绝给出占用值。旧入口继续保守拒绝新增布局。
5. 本轮没有清理入口。以后续作仍需当次租约和逐文件核对；掉电与遗留租约恢复不在本轮。

## 最小验收

- 用正式包资源生成并移动隔离索引，记录名册。独立核对原清单和文件不变、新进程重复确认以及占用增加的准确字节数。
- 覆盖不匹配名册、外来文件、链接、晚到目标、取消及发布后目录同步失败，保留原清单和文件。
- 包内定向复跑，实际 WK 回归普通搜索和定位。
