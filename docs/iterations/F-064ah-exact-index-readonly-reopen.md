## 范围

为内部持久索引增加一种仅重开现有同名册缓存的方式。缓存清单的范围、行 ID 与正文哈希全部一致时才启动原生读会话。普通窗口和旧增量模式继续沿用现有入口。

## 最小实现

1. 读取已存在的 App 私有槽。缓存未建立时直接返回缺失，避免新建数据根、槽或原生索引。
2. 在同一租约内校验清单及范围，再比较当次新授权快照的全部行 ID 与正文哈希。忽略顺序。范围不合、清单异常或内容名册不同，均在启动原生模块前拒绝。
3. 一致时以 reader-only 模式重开，按既有代数和命中核对规则查询。不应用增量或写清单，按既有租约收尾。清单预检只保护已知一致的正常缓存，原生读取仍可能加载存储正文，不作数据擦除或抗同用户篡改承诺。

## 最小验收

- 隔离冷槽保持缺失，正常缓存中同名册乱序能以 reader-only 查询。同 ID 正文变化、增加、删除、异范围、损坏或租约忙碌不启动原生会话。
- 对比包内资源的查询代数、命中、清单与索引文件 SHA，核对预检拒绝和读取后无原生增量或目录残留。
- 真实 WK 回归普通正文搜索、定位和退出。

## 继承约束检查

- F-002 沿用当前授权，离线留最终人工。
- 中文与外观沿用现有搜索面板。
- 命令与键盘沿用现有搜索入口。
- 安全与日志方面，清单只比较已授权快照，不用缓存还原文件授权。
