# F-064aw 退役索引移入待回收位置

## 范围

给已写入 v3 准备记录的私有索引提供内部显式移动。将原名 `index` 改为同一私有槽内的固定名 `.reclaim-pending`，保留清单和全部文件。普通窗口无此操作入口。

## 最小实现

1. 调用方提供精确范围键、代数及 v2 摘要。取得既有私有槽的同一租约，读取精确 v3 清单，识别仅原名存在与仅待回收名存在两种状态。两名均存在、两名均缺失、异常链接或额外文件时保守拒绝。
2. 在原名位置复核 v2 全量摘要、v3 稳定摘要及原生控制名册。使用已核对的私有槽和原索引目录描述符，固定名称排他移动。真实动作前再核对调用方、清单、目录、文件及租约。目标已存在时保留两边。
3. 移动后同步原槽目录描述符，再复核原名不存在、待回收目录仍是原身份、文件与 v3 摘要一致，且清单和租约仍匹配。若移动结果或收尾无法确认，返回 `UNKNOWN` 并保留现场。重复请求在待回收位置按 v3 摘要和已知格式复核，可返回已移动，省去重复移动和重写清单。
4. 保持旧查询、准备、预检及旧占用入口保守拒绝待回收布局。崩溃后仍在的租约继续按占用拒绝。当前移动不会释放磁盘空间。

## 最小验收

- 正式原生夹具经 v2、v3 和内部正式移动，核对原目录消失、待回收目录为原身份、全部文件与清单守恒。新进程重复请求不再调用移动。
- 覆盖占用、异常链接、布局和摘要失配、取消及移动后目录同步失败。确认遗留现场可由后续精确请求复核，旧入口继续拒绝。
- 包内复跑，真实 WK 回归普通搜索和定位。

## 继承约束检查

- F-002 沿用私有 App 数据范围，离线留最终人工。
- 中文与外观沿用普通搜索界面。
- 命令与键盘没有新增窗口入口。
- 安全与日志方面，接口不接收任意目录名，移动保持排他，回执不包含路径或正文。

## 验收结果

- macOS arm64 unsigned canary `0.1.0-alpha.233`，包标识 `1mmxcrnqh7dih`。正式包的保存模块与本机构建字节一致，增加固定的移动入口。包内 Bun 1.4.0 定向复跑 5 项通过、14 项条件跳过、18 条断言。隔离移动场景另有 69 条断言通过。
- 正式原生夹具移动后，原名消失，待回收目录仍为同一设备、inode 与创建时间。原生文件身份、内容摘要和 v3 清单保持原样。新进程在移动模块缺席时仍可确认已移动。原读写、预检、准备和旧占用入口拒绝该布局。
- 目标冲突、无清单、异常位置、摘要失配、取消和遗留租约按边界拒绝。注入移动后目录同步失败，返回 `UNKNOWN` 并保留现场，显式重试确认原待回收位置。用 alpha.232 的原生资源另行验证缺少移动入口时明确拒绝，原目录与清单保持不变。
- 真实 WK 回归普通搜索一篇两处命中、定位第二处 `[19, 23)` 和 ⌘Q 正常退出。夹具 SHA 不变，未创建索引槽，启动器退出 0，临时目录为空。
- 首次定向复跑发现旧准备入口遇到两名并存时错误码变化，修正后定向 22 项通过、13 项条件跳过、149 条断言。源码全量 1914 项通过、33 项条件跳过、1 项失败，39479 条断言。唯一失败仍是已登记的 FINAL-ISSUE-002 长空白超时。类型、Lint、文档、锁文件和差异检查通过。
