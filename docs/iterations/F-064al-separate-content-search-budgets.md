# F-064al 分离直接搜索和原生索引容量

> 状态：alpha.223 已通过本片非离线受托代验。前置 F-064ak 提交为 `c6b4d1f`。

## 范围

拆开现有搜索容量的用途，为后续扩大直接搜索文件数做准备。本片沿用现有产品数值、错误和可见行为，原生 `limited-v1` 保持独立。筛选前仍最多 16 篇，查询正文总量与单文件均为 64 KiB。

## 最小实现

1. 分开查询覆盖数、当前打开文档绑定数、独立文件句柄数、正文总字节及单文件字节。各处使用对应限制，保持 16 和 64 KiB 的现有值。
2. 直接路径的扫描捕获、磁盘读取、RPC、进度、结果合并和定位使用直接搜索限制。原生实验、私有索引快照和严格重开沿用原生限制。传输形状与既有错误不变。
3. 打开文档绑定、独立文件、文件夹数、片段和定位各自保留原边界。暂不提高容量或更改界面文案。

## 最小验收

- 复跑共享协议、客户端覆盖与正文预算、实际工作区读取和定位。检查既有上限仍完整通过，超限仍整次拒绝。
- 复跑原生名册与内部只读查询，确认未继承直接搜索容量。
- 包内复跑并在真实 WK 回归查询、定位和正常退出。

## 继承约束检查

- F-002 沿用当前授权，离线留最终人工。
- 中文与外观保持现有搜索面板。
- 命令与键盘沿用现有搜索入口。
- 安全与日志方面，容量拆分不改变授权或增加日志。

## 验收结果

- macOS arm64 unsigned canary `0.1.0-alpha.223`，包标识 `2pm9vnn975611`。包内 Bun 1.4.0 与正式原生资源复跑协议、客户端覆盖、范围、预览、定位、工作区快照及严格只读缓存，53 项通过、11 项条件跳过，412 条断言。临时目录为空。
- 共享验证分开检查打开句柄、独立句柄、覆盖文档、单文件和总字节。客户端保留原有非法正文与超限的错误优先级。直接读取和普通、保留文档定位使用直接预算，原生名册与内部只读继续走原生预算。三条实现分支交叉复核无阻断。
- 真实 WK 在隔离目录验证 16 篇可见文件时，能查询并定位第 16 篇的 `[8, 12)` 命中。显示隐藏文件后变为 17 篇，再次查询显示原有上限提示。17 个夹具 SHA 不变，应用数据未建立索引槽，⌘Q 后启动器退出 0，临时目录为空。
- 源码全量 1908 项通过、22 项条件跳过、1 项失败，39387 条断言。唯一失败仍是既有 FINAL-ISSUE-002 长空白超时。类型、Lint、文档、锁文件及差异检查通过。

下一片 F-064am 将普通直接搜索的筛选前覆盖从 16 篇提高到 32 篇，保留文件夹数、打开绑定、独立句柄、字节预算及原生索引限额。通过真实定位回归后再评估进一步的字节容量。
