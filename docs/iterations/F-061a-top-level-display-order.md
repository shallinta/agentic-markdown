## 最小技术方案

1. 新建纯展示顺序模型：输入当前顶层key集合和当前窗口顺序，保留仍存在key的相对顺序、删除失效key，新出现项按本次基础投影顺序追加末尾。首次无自定义顺序保持当前基础顺序。状态最多保存当前顶层项数量，不积累历史失效key，不读取磁盘或排序正文。
2. 覆盖去重仍由原投影决定：独立文件被新目录覆盖后从顶层及排序状态移除，保留其他根顺序；未来重新成为独立顶层时视为新出现项追加，不以路径猜测或复活旧授权。重扫同root handle保持位置，真正换根handle视为新根。规则只针对会话展示，不修改现有去重与身份。
3. 只重排 `children.get(null)` 的副本，items及各根子树保持。共用一个纯 `move(sourceKey, targetKey, before/after)` 操作，键盘邻位交换复用它。执行时用最新模型验证source/target仍为顶层；异步扫描、吸收去重、清空、选择和busy变化使旧拖动失效，不靠drag payload字符串直接提交。
4. HTML拖放或现有可用指针能力仅作为输入层，使用本地会话标记与当前key白名单；不接OS文件路径、跨窗口任意数据，不调用workspace open/授权/写入RPC。插入线仅出现于有效边界；根内内容不映射成隐式顶层落点。实现前核实际DOM事件与可取消行为，真实WK必须验，不以合成事件通过替代。
5. 顺序owner放在主窗口持久存在的controller或组件层，侧栏折叠/隐藏、模式/标签切换不会重置。本片**仅当前窗口运行会话**，正常退出后不承诺恢复排序；完整恢复仍属F-029/OBL-033/040，未来须在已授权根集合恢复后以正式稳定身份映射顺序，不能直接持久化当前handle。本片不新增设置schema、后台任务或存储，也不称F-061整项完成。
