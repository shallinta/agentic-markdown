## 已确认的本片最小方案

1. 固定`DOMPurify@3.4.16`：使用有限HTML结构标签白名单、禁止全部属性、`RETURN_DOM_FRAGMENT`返回片段。挂载前复核全部节点类型、HTML命名空间、标签与零属性；仅挂载净化片段，绝不挂载输入字符串。净化后序列化与输入严格相等作为额外保守展示条件；不相等、失败或不支持时整段`textContent`保留源码并提示。安全但会被HTML规范化的输入也可能降级，不相等不意味着恶意；此限制仅用于本片实验，不冻结F-023完整HTML行为。不使用`removed`为空作为安全授权。
2. URL只做纯分类，输出允许类别/拒绝原因，不访问目标、不授予路径或网络权限，不把分类结果当作导航授权。本片不会接入系统浏览器、文件打开或下载操作。
3. 继承当前CSP与隔离入口。合成输入仅来自固定样本，不开放任意HTML、用户路径或远端URL入口；结果只展示必要中文摘要，不输出完整正文、路径或AST日志。
4. 验证经本片内容入口生成的DOM不存在href、src、target、download、事件、样式等主动入口，捕获点击、辅助点击和提交的默认行为。只证明固定语料在该应用路径上的不可达性，不声称框架原生下载全面拦截。保留既有CSP和导航规则，不原生补丁、不扩大RPC权限、不进行下载PoC。
5. 链接未来由明确用户动作经协议校验后转既定路由：本地Markdown在主区预览，其他本地文件按对应规则交默认应用，http/https/mailto交系统应用。分类不等于文件授权；本片只验证分类，不接正式打开流程。系统浏览器负责网页打开后的安全，App仍负责协议、用户动作与不可信内容入口。
