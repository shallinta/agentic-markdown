# 单功能迭代文档

本目录保存每轮敏捷开发的唯一事实记录。模拟演练不创建迭代文档，也不改变正式 Backlog 状态；真实开发时，必须在编码前创建并由用户确认对应文档。

## 文件命名

```text
docs/iterations/<featureId>-<英文短名称>.md
```

例如：

```text
docs/iterations/F-001a-app-shell.md
```

功能拆分后使用稳定的切片 ID。不要用父功能 ID 混记多个可独立验收的切片，也不要因为排序变化而修改 ID。

## 文档生命周期

每轮启动与关闭先查[迁出能力登记](../deferred-obligations.md)并运行 `bun run check:obligations`。列出本功能全部主承接项，更新迭代引用；主承接已验收但仍有未关闭项不得视为完成。切片可分别承接，父功能未覆盖项须继续显式追踪。适用的用户批次授权可调整逐轮确认节奏，不免除文档、验证和验收证据。

1. 介绍当前关注层的规划、进度和可立即开始项，由用户选择本轮功能或切片；关注层由用户决定，未指定时默认建议编号最小且仍有未完成项的层；
2. 创建迭代文档并写入功能说明；
3. 讨论并确认本轮最小技术方案；
4. 讨论并确认最小 happy path（正常成功路径）测试；
5. 三部分全部确认后开始开发；
6. 实现中若产品行为、范围或关键技术路线发生变化，更新同一份文档并重新确认；
7. 实现后记录实际改动和真实自动验证，并把新增或变更功能同步到[产品功能手册](../product-feature-manual.md)，标注待人工验收；
8. 用户人工验收后记录结论和日期，同步更新手册状态及简短变更记录；
9. 更新切片、父功能和依赖层状态；
10. 提交和 push 分别等待用户明确授权，本轮结束后由用户决定下一项。

## 状态口径

2026-09-22 起，代码修改后每次重新打包都递增 alpha 开发预发布版本，具体规则见 [AGENTS.md](../../AGENTS.md)。打包前更新 `apps/desktop/package.json`，打包后核对产物版本，在本轮记录中写明版本、构建命令与结果；仅文档修改且不打包不递增。此规则不授权发布、标签、提交或推送。

- `未讨论`：尚未进入单功能设计；
- `设计中`：正在确认功能说明、技术方案或 happy path；
- `待实现`：迭代文档已经确认，但尚未开始编码；
- `实现中`：正在编码或自动验证；
- `待人工验收`：实现和约定的自动验证已经完成；
- `已验收`：用户已经明确确认通过；
- `待修改`：人工验收未通过或实现中发现必须修正的问题；
- `继承草稿`：基线中已有实现，但尚未按本产品规则完成讨论、测试和人工验收；
- `部分完成`：父功能已有部分必要切片通过，但仍有必要切片未验收。

F-002 使用 `持续约束` 状态：不单独开发、不作为完成前置、不计入独立功能验收分母；相关轮次在同一份迭代文档中记录适用约束及证据，发布前核对覆盖范围。

代码存在、界面可见、基础接线可用或继承测试存在，都不能把“继承草稿”自动提升为“已实现”或“已验收”。只有全部必要切片通过人工验收，父功能才可以标记完成。

## 最小模板

```markdown
# <featureId>：<功能名称>

> 状态：设计中
> 父功能：<父功能 ID 与名称；没有则写“无”>
> 前置依赖：<已满足的直接依赖；没有则写“无”>

<!-- obligations: none -->
<!-- deferred-obligations: none -->

<有承接项时将 none 替换为逗号分隔的稳定 ID，例如 OBL-001, OBL-002；同时更新登记表迭代链接。>

<切片未承接的同父功能剩余 ID 填入 deferred-obligations，并在范围外说明理由/后续切片；保持待承接，不允许用延期标记关闭。主承接功能的全部 ID 必须在所属迭代中声明承接或延期。>

## 继承约束检查

- F-002：<本地真源、离线、非编辑不回写的适用行为与验证；或不适用理由。>
- 中文与外观：<新增 UI 简体中文、浅深/系统外观；或不适用理由。>
- 命令与键盘：<统一注册、活动文档/选区上下文、键盘等价入口；或不适用理由。>
- 安全与日志：<不可信内容；新增 RPC 的版本/字段/大小/请求、权限/capability/revision 校验和稳定错误，异步 identity/hash 基线；匿名限额日志、持久设置保护；或不适用理由。>

```

模板中的尖括号是使用说明，创建具体迭代文档时必须替换，不得把占位内容提交为已确认设计。

F-009 起的正式迭代必须保留唯一的 `> 状态：...` 引用行，以及各一个 `obligations` 和 `deferred-obligations` 标记；无承接或延期时也显式写 `none`。验收状态使用 `> 状态：已验收`，日期和结论另写验收记录，不改用列表状态行，以便检查器准确识别。
