# 项目入口文档设计

日期：2026-09-04

## 目标

为项目补充轻量、可持续维护的入口文档，当前仅用于个人记录，不面向贡献者，也不把尚未实现的产品决策描述成已有能力。

## 文件与职责

### `README.md`

中文项目入口，包含：

- 一句话产品定位；
- 当前阶段和“尚无可运行版本”的明确说明；
- 精简的核心原则与 MVP 形态；
- 当前技术方向及仍需 M0/PoC 验证的边界；
- 现有文档入口；
- 下一步工作。

### `README_EN.md`

与 `README.md` 信息等义的英文版本。标题层级、事实、阶段和链接保持同步；允许为英语表达自然调整句式，但不得增加中文版本没有的产品承诺。

### `AGENTS.md`

使用中文约束在本仓库工作的编码 Agent。英文术语首次出现时提供中文解释。内容包含：

- 当前项目阶段和工作边界；
- 事实来源及冲突时的优先级；
- 不可破坏的产品约束；
- `CONTEXT.md` 中领域术语的使用要求；
- 产品决策文档的同步维护规则；
- 产品边界与候选技术实现的区分；
- 最小验证要求与 Git 操作纪律。

## 非目标

当前不加入：

- 安装、运行、构建或测试命令；
- 贡献指南、行为准则或 Pull Request 流程；
- 许可证声明；
- 发布日期、版本承诺或完整路线排期；
- 全量 MVP 功能复制；
- 尚未完成 PoC 的依赖版本、性能数值、schema 或实现细节。

## 事实来源

文档只压缩呈现已确认信息，不创造产品决定。事实按以下顺序解释：

1. 用户当前明确指示；
2. `docs/product-capability-register.md` 的当前基础结论和能力表；
3. 同一文件中日期更晚的决策记录；
4. `CONTEXT.md` 的领域术语；
5. 外部调研仅作为证据，不自动成为需求。

## 维护与验证

- README 只保留稳定摘要，详细决定链接到产品能力总账；
- 中文 README 发生事实变化时，同步更新英文 README；
- 工程初始化后再补真实、已验证的命令和目录约定；
- 文档改动至少执行 `git diff --check`，检查内部链接、README 等义性，以及 AGENTS 规则是否与当前决策冲突；
- 未经用户明确要求，不提交或推送后续改动。
