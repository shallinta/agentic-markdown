## 功能说明与范围

对当前进程已打开、已授权的 Markdown 文档观察外部变化，提供就近中文非阻塞状态提示；包括同一身份正文变更 `content-changed`、路径确认不存在 `missing`、叶文件身份改变 `replaced` 和无法可靠复核 `unavailable`。未发现差异时为当前已确认状态，不凭一次 watcher 事件直接认定修改或删除。“只读状态提示”表示观察不写磁盘，不是把所有编辑模式变成只读。

本片不自动刷新或提交候选内容，不推进 disk baseline、mirror 或文档 revision，不改变内存 buffer、编辑 dirty、历史、模式及选区。自身成功保存回声依据已提交 token 对应的身份/hash 识别，不用固定时间窗口忽略事件。权限能力仍使用现有独立 capability 规则，不能把无法检查等同“没有变更”。

局部承接 OBL-005（受控 watch 与身份/版本隔离）及 OBL-016（合并、取消与限流）；OBL-011 可靠外部身份跟随明确延期。根事件发现、文件树自动变化、可靠 rename、新路径授权、clean 自动刷新、dirty 三方冲突、重建原路径及复制入口留 F-027/F-028 等后续，完整父功能和义务开放。硬前置为现有单文件授权/Document Service、保存身份/hash 基线、生命周期与窗口提示，不等待完整目录树或 F-026b 通过。

## 最小技术方案

1. 现有 `watchGrant` 仅监听叶文件与父目录并发送 capability hint，不能冒充正文监听已交付。本片复用或分离该入口，让文件/父目录事件只触发受控复核，不将事件中的文件名或路径作为新授权；重聚焦也只复核当前已授权叶文件，不递归发现其他文件。
2. 后台以 handle/documentId、授权 lifetime、观察 generation、预期已提交身份/hash/revision 捕获任务上下文。读取仅用于有界身份与内容 hash 比较，不调用会提交 snapshot/baseline/mirror 的普通读取路径；复核现有授权、祖先和叶文件约束，前后身份不一致拒绝结果。missing 必须确认是目标不存在；权限、父目录失效或不确定错误归 unavailable，不猜 rename，不读取替换后未授权正文。
3. 每文档合并重复 hint，有限并发/队列且 latest-wins，保存优先：在途写入先结算再按新提交基线复核。自身写后身份变化只在对应提交 token 与实际身份/hash 一致时消除回声，紧随的外部不同内容仍须报告；失败或不确定保存不得冒充已提交状态。具体可调资源值由实现测量记录，不预设性能门禁。
4. 观察结果是独立元数据，不是新的正文真源。RPC/事件运行时校验，只返回有限状态与绑定标识；客户端仅应用当前 lifetime/revision 的结果，关闭/释放/重选/保存换代/销毁后丢弃旧回执并释放 watcher、定时任务，不宣称正在阻塞的文件系统 I/O 可硬取消。重复结果不反复打扰用户或触发解析。
5. 提示区分“磁盘内容已变化，当前显示未更新”“原文件不存在，内存内容仍保留”“原路径文件已替换”“暂无法检查文件”等状态，不自动切模式、刷新正文、写回或新建文件。现有保存前 identity/hash 保护不得弱化；缺失/替换/外部变化不能被提示误写为可安全覆盖。
6. 安全继承（主线确认）：按基础结论 276/277 与 CONTEXT，missing 原 clean 文档也可能只剩唯一内存内容；replaced 无法确认原文件其他位置，亦保守保护、不猜 rename。不修改编辑 dirty 并不豁免关闭、退出、重读等可能丢失内容动作的放弃确认；复用或补足既有关闭机制的最小保护判定，保留 buffer，不因观察结果删除 grant 而静默丢失，也不重建磁盘路径。完整冲突工作流仍不在本片；超出此安全接线的实现变化先报告主线。

2026-10-04 主线实施前补充确认：同身份 `content-changed` 也表示原 clean 内存正文尚未接受外部版本，纳入相同独立丢内容确认保护；不改编辑 dirty、保存状态或磁盘基线。已确认风险不因后续 unavailable 或同路径再现而静默解除。

现有 client `protect` / `hasDirty` / 同路径替换确认仅检查编辑 dirty，本片须统一以独立 `needsDiscardProtection`（或等价判定）覆盖 close、clear、手动重读、native reload/quit/update 及重新选择产生的同路径替换。missing/replaced 保护仅由经验证的新状态或用户明确舍弃解除，不因权限错误或旧回执消失。后台 probe 不复用 `DocumentService.read` / snapshot+commit：现有 read 会推进基线，且 FILE_CHANGED 会删除 grant，均不符合只观察边界。

既有 canonical discard participant 仅转发 `controller.hasDirty`，固定“未保存变更”文案也不能冒充本片所有风险原因；实现需接独立风险判定与适当中文确认文案，不污染 `isDirty` / `getSaveStatus`，不提前冻结新 schema。已确认 missing/replaced 后出现 unavailable 仍保留丢失风险。

## 最小 happy path 与异常验证

- 临时已打开文件经外部同身份写入，clean 与 dirty 均收到对应状态；buffer、dirty、历史、模式、baseline/mirror/revision 不改变。重新确认无差异不生成额外正文或解析事务。
- 自身保存产生 watcher 回声不误报；自身写入后紧接外部写入仍报告。覆盖保存进行中、失败/不确定保存、重选/关闭后晚结果以及同路径新身份，不能旧结果覆盖新状态。
- 删除显示 missing 并保留内存；即使原 clean，关闭/退出/重读仍须保护确认。原子替换显示 replaced，同样保守保护原内存，不直接跟随新身份、猜 rename 或刷新；权限失效、父目录替换和检查错误显示 unavailable，不误判不存在。
- 高频同文件及多文档事件合并有界，保存不被饿死；取消/销毁释放资源，重聚焦只访问已授权叶文件。未打开文件及根内新增文件不因此被发现或授权。
- 对原 clean 的 missing/replaced，逐项覆盖 close/clear/手动 reload/native reload/quit/update/同路径重新选择替换的确认与取消保留；未知权限错误、旧回执不能解除风险，编辑 dirty 与保存状态不被伪造。Q-29 完整 1/100/1000 根及索引事件风暴验证留父功能，本片仅已打开叶文件合并测试，不宣称达到完整范围。
- 真实 WK 验证两文档隔离、clean/dirty 外部写提示、自身保存回声、删除/替换及三模式状态保持；临时样本操作不修改用户文档。自动受控竞态与故障注入不冒充真实窗口捕获，记录实际耗时/资源值而非性能承诺。
