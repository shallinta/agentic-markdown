## 最小技术路线

1. **统一语法换代。** 扩展固定Lezer adapter与独立canonical adapter，升级shared profile/version；BomAware、编辑Worker请求/回执/最外decode、canonical缓存/请求及inline/list/quote局部验证全部沿同配置。旧/缺配置及晚回执拒绝。保留删除线公开guard，不把canonical依赖拉入编辑bundle，不新增全文解析通路。
2. **可靠位置。** 只从当前完整可靠语法树Task/TaskMarker及所属ListItem取得三字符原标记；执行时核实际`[ xX]`字面及解析身份，CM逻辑offset通过既有raw通道映射，禁止用全篇regex或渲染文本反推位置。BOM/CRLF/loneCR保持原raw，点击变化为单一ASCII字符。partial/长行保护/无法可靠对应时保留原文，不装可写控件。
3. **编辑控件。** 使用受控本地复选框widget，有限视口安装，状态来自当前源码，不能以DOM.checked为正文真源。标记触及后的原文显露与现有编辑显隐原则一致；组合输入期间不改变干扰性装饰。widget重用/销毁不能保留旧doc或旧Text执行能力。可访问中文标签、checked/disabled与可辨焦点样式须核；仅该控件支持自身原生键盘激活，不增加全局键位。
4. **点击授权与焦点。** 点击是对当前可见任务控件的明确意图，不要求此前正文已经hasFocus（否则从侧栏返回点击可能失效）；但必须目标确属当前挂载editor及当前document/session，不能借全局最后文档。pointer/键盘激活开始记录本次短期意图与当前state/Text/标记，组合输入、只读、busy/frozen/inputBlocked、safe、非editing、失活/卸载时不出票；若手势开始时被拒绝，之后compositionend不能让同一尾随click复活。完成激活前同步重验并消费，再构造一次事务交controller，旧state/重复事件/标记或权限变化均拒绝，不改绑最新位置。事件处理不能先强制focus来提交/取消IME；成功后按既有view生命周期恢复正文焦点，失败不抢焦点。PoC及正式接线需验证pointer默认焦点行为，不凭静态设计声称可靠。
5. **阅读/源码安全。** 阅读采用固定非活动状态呈现（例如受控span加中文状态说明），没有checkbox写回事件、可聚焦表单或新增URL属性；源码只原文/颜色。不得为此向原始HTML净化allowlist开放input或任意role/属性。若受控阅读审核需增加精确状态class/属性，仅批准固定枚举，与原始HTML权限分离。

### 真实窗口键盘未可达：最小诊断与候选方案（未批准实施）

**诊断反馈环边界。** 现有EventTarget模型只能验证到达控件后的事件，不会在原故障上变红，不能用于关闭此问题。后续需主线保留上述原序列的工具调用/AX结果作为红灯基线，最小自建文档含两个可见任务、正文光标不碰marker。通过判据必须是不用鼠标聚焦checkbox时获得其可辨识焦点，Space/Enter精确改一个marker；单看按键返回成功或模型调用focus不足。当前子线没有亲自执行的独立红灯命令，因此尚不宣称完成技能的反馈环/最小化阶段；以下是假设及待批准验证计划，不是根因结论或修复完成。

**有界候选假设（测试前列出）。**

1. 浏览器默认Tab遍历没有进入contenteditable内widget；若是，显式聚焦当前连接的受控button可使其本地键盘处理可用，而只改keydown处理不会改善默认入口。需比较同一按钮的显式聚焦与默认Tab，不能泛化为系统原因。
2. 焦点或状态更新使原widget被替换/显露；若是，聚焦后当前activeElement或目标DOM身份立即变化，单纯显式focus仍不能稳定操作。应核聚焦前后连接身份与状态，不放宽陈旧state守卫。
3. 焦点出口的Tab在到达应用原handler前已放行；若是，仅把入口加在原domEventHandlers里不会执行，而DOM capture可观察同一Tab。此机制有本地源码依据，但不是默认Tab遗漏控件的完整根因。

**已读本地公开依据。** `@codemirror/view@6.43.12/dist/index.d.ts`公开`setTabFocusMode(to?: boolean|number)`，作用是放行Tab/ShiftTab给浏览器；没有公开getter。对应实现keydown在tab-focus生效时于自定义事件处理前早返。现`source-indentation-input.ts`通过公开`toggleTabFocusMode`保留macOS物理Alt+Shift+M，不能在原indentation handler简单增加分支并假定可捕获已放行Tab，也不得读`view.inputState`等私有状态。浏览器Element.focus、contentDOM捕获事件与ownerDocument.activeElement可作为局部焦点入口；公开API能做此事不证明WK实测可达。

**拟最小方案，供主线选择。** 优先只增加“正文Escape后下一次普通Tab进入当前可见任务”的局部入口，保留原Alt+Shift+M实现与无任务时全部原行为，不尝试镜像不可公开读取的CM tabFocusMode。以contentDOM capture观察来自当前正文而非widget/查找栏的无修饰Escape，登记短期一次焦点意图；有效期可与已读当前CM Escape出口的2秒一致，但这是本地入口策略，不当成公共getter。下一次无修饰Tab且原文/模式/session/当前view仍相同、未组合/非safe/未冻结时，才按当前实际连接DOM顺序聚焦首个可见受控任务button并消费意图；不改变选区、raw、history或授权写入。其它键、失焦/组合开始、状态/权限变化、卸载取消，不复活；无目标/聚焦失败则不吞原Tab。只读文档可以聚焦状态但仍不得出票写入，源码/阅读/safe无此入口。

若主线还要求Alt+Shift+M同样直接进入任务，应另明确局部焦点意图与原toggle的关系后实施，不能凭私有模式或臆造getter推断当前开关；本轮最小入口无需改原快捷键。
