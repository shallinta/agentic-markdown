## 范围

在私有索引仍位于原处时，记录将来移动所需的身份信息。新记录由内部显式请求产生，沿用退役槽单一清单和租约。

## 最小实现

1. 调用方提供精确范围键、代数和 v2 退役摘要。在既有私有槽租约内，重新核对当次的摘要、原生格式、实际文件名册及当前状态。旧退役标记、活动槽、身份失配和已有异名目录均拒绝。
2. 原清单原子更新为精确 v3 `reclaim-prepared`。保留 v2 摘要，另存一个有版本标识的 SHA-256 摘要，绑定范围、代数、原摘要、目录稳定身份和排序后的全量文件元数据。目录的设备、inode、创建时间、属主和模式纳入新摘要，目录的修改时间和状态变更时间排除。原生文件只读核对。
3. 发布前同步复核清单、目录、文件、租约和调用方。发布后同步持有的私有目录描述符并确认记录及租约。确认不了结果时返回 `UNKNOWN`，保留现场。重复请求只有在当前原名目录、两份摘要和原生布局都匹配时才确认，不重写清单。旧读写、退役和 v2 预检入口拒绝 v3，不启动 Worker。
4. 原名目录与全部文件保留。进程中断后若租约仍在，后续调用按占用拒绝。正常退出后跨进程可复核记录；掉电持久性和遗留租约恢复不在本轮。

## 最小验收

- 用正式原生资源生成 v2 退役夹具，再写入 v3，独立计算摘要并核对目录及文件不变。新进程验证重复请求、原入口拒绝以及缓存占用。
- 覆盖错误摘要、未退役和旧标记、异常布局、占用及发布前取消，核对原清单保留。
- 包内定向复跑，实际 WK 回归普通搜索和定位。

## 继承约束检查

- F-002 沿用私有 App 数据边界，离线留最终人工。
- 中文与外观沿用普通搜索界面。
- 命令与键盘没有新增窗口入口。
- 安全与日志方面，清单记录匿名键和摘要，不写入原文或工作区路径。
