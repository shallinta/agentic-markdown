## 功能与既有规则

交付当前活动、已打开且授权仍存活的Markdown文档“在 Finder 中显示”。允许dirty与readonly：定位磁盘位置，不保存、不更改正文、历史、选区、标签或文件。无活动文档、missing、busy/frozen、IME候选或安全交互禁止时不可发起；旧目标、已关闭/撤销授权、替换文件及验证失败仅局部中文提示，不自动重选或定位父目录。

依据总账W-13（752、1515行）：后端原生reveal/select API、结构化路径、不拼shell、文档内容不可触发；不存在/未授权/调用失败不改状态。F-060硬前置F-004a受控授权已具备，F-006命令注册与活动会话消费者已具备；无需等待完整外改冲突或跨重启恢复。此片不交付W-14外部编辑器、文件树目录定位、平台持久授权恢复。完整F-060及OBL-060其他消费者保持开放，离线留最终人工。

## 公开接口调查与推荐

实际SDK入口来自Electrobun 2.0.1的`.hutch/devkit`，不是node_modules缓存中的1.18.1：`api/sdks/main/core/Utils.ts:14`公开`Utils.showItemInFolder(path)`，调用`ffi.request.showItemInFolder({path})`；`proc/native.ts:603,2285`为原生cstring→void。可直接使用公开API而不自写Bun FFI。现`src/bun/native-files/index.ts:143`的revealPath经detached `open -R`并吞退出结果，不能用来宣称已满足本片原生API与失败语义；本片应给既有native-files依赖注入公开SDK适配，不扩其他平台或改openPath。

重要限制：该SDK API返回void，无法证明Finder已选中，也不能区分原生层静默失败。可以检测授权/路径校验失败和SDK同步throw，不可显示“已成功定位”或把void当成功凭证。推荐先按“已发出定位请求、无成功toast”接入，并真实WK验证Finder选中文件；**若主线认为W-13要求所有系统失败可观测，则此路线不充分，需先调查原生返回契约而非伪造成功**。

现Node-API桥仅`native/save-primitives.c`和`directory-watch.h`，构建脚本clang C bundle，无AppKit框架/Objective-C源。可技术上增加ObjC适配，但目前未调查完成NSWorkspace线程/返回语义，也未批准新增桥。已有公开SDK已提供功能，因此不默认另建桥或使用内部ffi符号；SDK void限制如成为必要阻断，再单独收敛，不实施两套路由。

## 最小typed接线方案

1. 命令注册一个中文“在 Finder 中显示当前文档”，通过现有可见按钮或菜单入口调用；不新造快捷键。命令以当前活动会话的handle/documentId捕获目标，前端不传path；只读/dirty可用，遵守controller现IME/busy/frozen guard。菜单关闭或跨文档后的迟到回执只允许对应当前请求反馈，不改变选择与焦点恢复规则。
2. 后端严格校验固定请求字段、requestId与handle；在DocumentService内部从grants取权威路径，不用locations数组给出的裸path当授权。捕获grant对象/服务epoch及目标documentId；用现`verifySingleFileAuthorization`加scope.verify核当前文件与目录身份，打开descriptor使用O_RDONLY/O_NOFOLLOW/O_NONBLOCK，finally关闭。已有asset verify路径可作为接线参考，不读取正文、不刷revision或更新基线。
3. 每段await后核grant仍同对象、epoch/授权仍有效、目标未释放、无写屏障或保存替换；最后核验与调用原生API之间不插await。复用取消请求机制防已取消/已关闭目标晚调用。前端目标切换可取消未提交请求，已发给OS的请求不可撤回；不可声称跨进程绝对同步当前焦点。文件校验与OS消费之间存在TOCTOU窗口，保留事实，不宣称文件系统原子定位。
4. native适配仅接后端已验证绝对路径，公开`Utils.showItemInFolder`同步调用，catch映射稳定中文错误，不泄漏OS原始错误或路径日志。返值命名为request-dispatched而非revealed-success；如果采用其他失败可观测方案，先更新本唯一并经主线批准。
