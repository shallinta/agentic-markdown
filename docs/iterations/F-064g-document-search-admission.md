## 本片交付

为隔离或其他可信 Bun 内部调用增加短生命周期的查询准入票据。准入时检查文档服务的授权及在途操作。在查询期间授权状态变化时，旧票据失效，查询停止交付命中。票据仅是内存中的有效性检查，不持有写锁。用户打开、保存或关闭文档时，查询让步，相关操作按原有流程继续。

本片仅在 F-064f 的自建夹具和内部集成测试中使用票据。正式工作区查询仍需解决编辑缓冲区的内容版本，暂不接普通 RPC 或发布正式界面。

## 现有接口的边界

- `bun/documents/index.ts` 的 `locations()` 是现有 grant 的即时视图。文档 revision/hash 描述已知磁盘版本，镜像在打开和保存时更新。渲染层的编辑缓冲区在 `client/documents.ts`，Bun 当前无法以镜像证明它没有未保存修改。
- grant 与编辑缓冲区的寿命并不一致。常规 `closeTab` 清掉 tab 和编辑器，但保留供重开的 entry 及其 grant。反过来，Bun 的 `read` 遇到 `FILE_CHANGED` 会撤销 grant 和镜像，客户端收到失败后可保留旧编辑器并标记 stale。工作区撤销 scope 时也会释放 grant 和镜像。grant 数为零只描述 Bun 当下的授权，不能当作编辑器已清空的证明。
- 文档服务的 `epoch`、`selectBarrierGeneration` 与 `saveStartGeneration` 分别覆盖处置、写屏障与保存。它们无法覆盖一次普通授权打开后又释放的完整交错。`withWriteBarrier` 会影响保存和打开准入，后台查询不使用它。

## 最小实现

1. 在 `bun/documents/index.ts` 让文档服务内部签发 `beginSearchAdmission(): { current(): boolean } | undefined`。初始准入只允许无 grant，且无选择、排队或执行中的文档任务、保存、刷新接受、创建或目录变更屏障及处置。先按整个文档服务保守拒绝，避免以路径推断授权归属。
2. 用单调代数标记会改变查询准入的操作。授权入口 `select`、`openAuthorized`、`openCreated` 应在受理时推进代数，避免查询中出现“打开后释放，状态看起来又为空”。审查 `read`、保存、刷新接受、grant 撤销、目录变更及处置入口。对于在无 grant 时不能开始的操作，可依赖既有准入条件，但须以测试或代码检查说明。新代数只废弃旧查询，不改变前台操作的调度。
3. `bun/workspace/index.ts` 的 `searchSnapshot` 从所属文档服务取得票据，复用根代数、扫描版本、取消和 close 收尾校验。进入 native 后仍等待原有收尾，`UNKNOWN` 优先。初始准入失败返回暂不可用。中途失效拦截迟到的成功结果，已产生的其他失败码可保留。
4. 后续切片若要把命中用于打开真实文档，需为索引实际读取的字节生成 Bun SHA，并绑定扫描条目、根代数。打开时以受信的文档快照 hash 重新校验后再使用 UTF-16 位置。单次目录读取不保证所有文件来自同一磁盘时刻，也不能代替未来未保存缓冲区覆盖。

## 最小验证

- 合成目录在无 grant、无在途操作时可查询并命中。持有任意 grant、授权尚未完成或文档服务已处置时不签发票据。
- 用受控异步点交错查询与授权打开。打开、释放后 grant 数再次为零，旧票据仍失效，迟到命中无法交付。新的无 grant 内部查询可以重新准入。
- 查询期间打开或保存仍按文档服务原有规则进行。覆盖查询已进入 native 后发生失效，确认保留 close 收尾及 `UNKNOWN` 优先级。
- 回归真实窗口隔离夹具与定向类型、测试及独立复核。记录 grant 被撤销但渲染层仍可能保有 stale 编辑缓冲区这一边界，不把票据验收扩大为正式用户搜索验收。

## 实现与源码验证

三条新授权入口在首次异步等待前推进查询授权代数。票据同时捕获现有的 `selectBarrierGeneration`，使创建、目录变更及写屏障即使进入后又退出，也会废弃旧票据。定位或用默认应用打开只在操作进行中阻挡查询。读、保存和刷新接受须持有 grant 才能开始。

定向测试 7 项通过、4 项外层条件跳过、0 失败，44 条断言。四个内层均在隔离子进程执行。覆盖授权入口同步失效、打开再释放、短暂写屏障，以及真实工作区扫描后用模拟索引回执验证迟到结果被丢弃、`UNKNOWN` 优先。类型及受影响文件的 Lint 通过。
