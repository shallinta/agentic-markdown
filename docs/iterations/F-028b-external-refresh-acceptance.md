## 功能说明与范围

在 F-028a 的无副作用候选读取基础上，提供内部受控接受与结果确认能力。仅接受服务实际持有、仍属于原授权与基线的候选；成功接受后更新 Document Service 的内存磁盘基线、revision 和 mirror。此操作不写磁盘，不是 durable 保存，也不证明磁盘此后不会变化。

同一接受操作允许重复请求并查询实际结果，不能因重复或晚到调用再次推进 revision。没有记录或记录被后续操作取代时，查询不能把“无法确认”伪装成“未提交”。返回值与服务内部结果互相隔离，调用者修改返回对象不得篡改记录。

本片仅扩展内部 TrustedDocumentService，暂不增加 RPC、UI、实验台或用户命令，不连接 clean 自动刷新，不改变当前编辑正文或用户交互，不实施输入冻结。F-027a 现有观察提示保持。普通 1 MiB、UTF-8/BOM/换行保真及原授权边界不变。

## 最小技术方案

1. 接受输入只引用 opaque handle、服务候选 token 与操作身份/代次，不能输入任意路径或候选正文。候选内部数据不作为公开可变接受载荷。严格校验输入后，捕获原 documentId、授权生命周期和预期基线。
2. 接受前再次读取并复核原授权叶文件、祖先/目录 scope、读取前后身份一致性与真实内容 hash。F-028a 的 checkBinding 不是磁盘最新证明，不能替代本次复核。候选之外的新 hash、missing、replaced、越权、超量或非法编码均拒绝，不 regrant、不猜 rename。
3. 接受与既有保存/普通读取提交使用明确的互斥或串行边界；最后检查与内存提交之间不得插入可使原基线失效的异步步骤。成功时基线、revision、mirror 作为同次服务状态变更，revision 只推进一次；候选失效及旧观察换代遵守既有规则。此处不是写盘事务，不增加恢复日志。
4. 每文档/授权生命周期使用有限结果记录与单调操作代次。重复同一操作只返回已确定结果或合并在途任务；同代次不同操作身份/参数不得冒充重试。记录淘汰后仍须拒绝旧代次重执行，不累积永久历史 token 集合。保存、读取或其他新基线建立后，旧接受重试仍不能把旧候选再次写回内存基线。
5. 查询明确区分能够证明的结果与未知/已取代状态；结果记录返回独立副本。超时或取消等待不意味着后台没有接受，已提交结果不由普通取消改写成失败。具体字段按实现所需确定，不在本片冻结完整跨进程协议。
6. 已开始的接受纳入适当 settlement（等待结算）边界：保存、普通读、withWriteBarrier、退出等待及销毁不能在接受未结算时错误报告安全完成，也不能相互等待形成死锁。释放/撤权使未提交任务失效，完成后的旧请求不复活 grant。每个文档只保留有限在途/待执行状态，实际读取全局有界，前台保存优先；不能仅以 opened-doc 数量说明同时打开的文件句柄有界。
7. 不引入消费者时保持内部服务验收；真实临时文件集成验证基线/镜像、结果重复及交错，受控故障注入验证未知结果与取消边界。不为验证基础能力增加生产实验 UI。

## 最小 happy path 与边界验证

- 原服务打开临时文件，外部同身份修改，取得候选后接受；内容/hash 与候选一致，revision 仅增加一次，mirror 建立正确新基线，磁盘字节/hash 不因接受改变。
- 同一接受并发或重复调用获得相同确定结果；模拟回执丢失后查询仍能确认接受事实，不二次提交。调用者修改返回正文、元数据或嵌套对象不改变后续查询。
- 接受前外部再次修改、替换/缺失、祖先或 scope 失效，以及候选丢弃/更新：拒绝旧候选，不扩权，旧服务基线不被失败路径误改。
- 接受与真实保存、普通重读、释放、撤权、写屏障、退出等待和销毁分别交错；验证在途结算、取消前后结果、无死锁与晚回执隔离。真实 Node-API 保存与受控暂停分别标注，不冒称真实窗口竞态。
- 接受后旧 mirror 不能作为当前镜像直接写入；新基线可走既有安全保存链路；外部随后再次变化仍触发观察/冲突保护。
- 多轮接受、保存和重读之后，旧操作不能再次执行，查询 unknown 不等于未提交；有限账本与有限并发有可核对证据，不为历史请求数量建立永久增长集合。
- 记录本片实际样本规模、耗时、失败与验证限制，不设置性能数值门禁。不因后台基础通过就标产品自动刷新已可用。

## 实际改动与验证

最小方案经主线批准及独立 Spec 核对 0 阻断后，已实现：

- 内部 `acceptRefreshCandidate` / `queryRefreshAcceptance`，不进入 RPC 或 UI。服务从私有候选取得 lease，调用者不能传正文或任意路径；接受重新校验身份、scope、实际 hash 与读取前后元数据，最后所有 await 完成后同步检查生命周期/基线并 commit。
- 账本按 live grant 授权生命周期保留一条最新结果与单调 sequence；一个全局接受任务，未获准请求返回 unavailable，不冒称它已执行或确定未执行。重复相同操作返回独立副本，相同身份不同参数与陈旧代次不能重执行。记录被新操作取代返回 superseded；释放/销毁后 unknown，均不等同未提交。
- committed snapshot 是该操作的历史回执，不是当前基线有效证明；随后成功保存或普通读取不会把该历史事实改成未提交，也不能借重试回退当前基线。提交开始后发生无法归类的异常返回 unknown，不冒称确定拒绝。
- 保存请求优先失效相关候选并等待在途接受结算，再运行原保存校验；普通读取/选择在接受期间 BUSY，不交织提交。waitForSaves 同时等待接受；写屏障/退出与 dispose 使在途接受不能越过屏障提交，并等待结算。释放/撤权移除候选与记录，不复活句柄。
