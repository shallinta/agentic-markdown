## 功能说明

在 A / F-012j 确定当前任务处置后，为当前自有可重建编辑语法缓存建立所有权、可核算成本、分类与总预算及安全释放规则。正文、未保存变更、权威编辑状态、选区与撤销历史不可驱逐；不能通过丢失用户状态降低统计数值。若没有安全可释放冗余，不承诺硬封顶，须报告实际边界，不能宣称完整责任完成。

## 最小技术方案

1. 首先记录实际所有权清单：主线程语法树/序列化副本、Worker 派生树与传输对象、待处理引用等哪些实际存在、是否共享、由谁释放。latest.tree 与 CodeMirror 可能共享同一 Tree，Text 引用也不等于新全文，不重复计费；瞬态传输副本与长期引用分开。当前只有一个活动文档、非活动解析已释放，不假设需要全局 LRU。
2. 为当前可重建类别定义可重复的成本估算和总账；可精确核算的缓冲区与估算对象成本明确区分，无法观测的 Worker/引擎/OS 内存记未知。预算依据本轮普通/密集样本和实际持有量选择，不当硬门禁、不等同 RSS 或 GC 实际回收字节。
3. 只控制公开接口下自有可释放冗余；不能精确控制的 CodeMirror 内部缓存明确排除并保留完整余项。预算超限不得关闭当前活动语法呈现、隐式退同步、安全降级或反复驱逐活跃树以凑数字。具体参数及处置以实施时样本验证补记，不提前构建未来全局 LRU 框架。
4. 与 A 的取消/合并所有权对齐，清理不能解除会话隔离或让旧回执重新占用预算。若维持产品体验需要关键路线/行为变化，先更新本文件重新确认。

## 最小 happy path

- 普通及密集样本完成解析、编辑、切标签再返回，记录各类别和总可核算成本变化；清理后按当前文本重建，语义树一致。
- 对相同输入重复编辑/释放，观察账目不积累失效持有量，不以统计归零冒充 OS 实际回收；有共享数据时不能重复计费。
- 清理前后正文/BOM/混合行尾、选区、历史/撤销重做、模式、保存及 dirty 不变；后台旧回执和销毁不能复活已释放缓存。结果与人工体验分开记录。

## 实现与验证进度（2026-09-28，以下为 alpha.39 构建前历史）

本片只给当前自有语法树引用建立成本账目：Tree/TreeBuffer 对象按模型估算，缓冲区实际 byteLength 单列，同一树或 backing buffer 去重。Text 是权威文档共享引用，不另计一份正文。解码后每个被接受树仅估算一次，不在每键或 snapshot 时重复遍历；CodeMirror 内部缓存、Worker 堆及 OS/RSS 仍未知。

当前仅一棵活动树；活动分类和总软预算均为 1 MiB **可核算派生成本**，与普通文档 1 MiB 上限是不同概念。超额活动树仍保留并记录 pinned excess，不关语法、不退同步/安全模式、不制造重解析循环。自有 wire 与过期树长期保留量基线已为零，本轮没有证明内存减少；销毁清空自有引用不等于 GC 或 OS 已回收。完整 OBL-020 仍开放。
