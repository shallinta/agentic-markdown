# F-064be 按序清理索引收尾旁车

## 范围

用固定 v4 清单核对并逐份移除收尾旁车。先移除历史名册，再移除空目录确认记录。每次请求只针对一份，v4 清单留到最终释放。开发验收仅使用隔离夹具。

## 最小实现

1. 内部显式请求提供范围键、代数、v2 摘要和固定记录类型。取得既有槽租约，读取不超过 4 KiB 的规范 v4。只接受两个目录名都缺失，且旁车呈两份都在、只剩确认记录或均缺失三种状态。所有现存记录的身份及字节 SHA-256 必须匹配。
2. 使用私有槽和所选文件的描述符。实际操作前复核清单、现存记录、租约和调用方。原生入口根据固定类型选择唯一名称，验证原名和待回收名缺失，随后用 `unlinkat` 移除，确认名称缺失及持有文件链接数归零。
3. 同步私有槽并重新核对 v4、旁车顺序和存留记录。所选记录已缺失时只同步和复核，不移除下一项。结果无法确认时返回 `UNKNOWN`，保留 v4，供同目标同类型重试。
4. v4 清单不改写。旧入口继续拒绝使用该槽。最终清除 v4、遗留租约恢复、自动清理与槽位复用另行承接。

## 最小验收

- 正式原生隔离夹具写入 v4 后先移除名册。新进程复核同一类型缺失，再显式移除确认记录。逐次核对 v4 和其他存留记录不变。
- 覆盖错误顺序、记录被替换、异常链接、目录重新出现、租约、取消和移除后同步失败。同类型重试不会跳到下一项。
- 包内定向复跑，实际 WK 回归普通搜索和定位。

## 继承约束检查

- F-002 沿用私有 App 数据边界，离线留最终人工。
- 中文与外观沿用普通搜索界面。
- 命令与键盘没有新增窗口入口。
- 安全与日志方面，调用不接收路径或文件名，回执只含缺失状态。

- macOS arm64 unsigned canary `0.1.0-alpha.242`，包标识 `5r0b2utq26v2`。包内 Bun 1.4.0 定向复跑 5 项通过、28 项条件跳过、32 条断言。隔离旁车清理另有 128 条断言通过。
