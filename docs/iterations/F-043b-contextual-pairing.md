## 功能说明与已确认边界

依据能力总账 E-04：编辑与普通源码支持圆括号、方括号、花括号以及 ASCII 单双引号的上下文感知配对，支持选区包裹、已有闭合符跳过、IME（输入法组合输入）避让及单步撤销。源码须兼容 F-044b 多选区，编辑仍保持单选区；阅读只读，安全源码保持既有极简隔离。

用户已明确：普通同类引号即使来自原有正文或粘贴，也应跳过；转义时正常插入。不是仅跳过本轮自动生成的引号。已有一般括号闭合符的具体原生行为也必须验证，但不将新引号决定擅自扩大为其他未明确的特殊规则。

不增加反引号、三引号、矩形选择、补全、列表续写、配对设置或快捷键。本片不默认启用 Backspace 成对删除；不修改 F-028c 撤销历史决定。引号新决定不倒写为 F-044b 已交付功能。

## 2026-10-10 用户授权后的最小生产方案（待主线批准）

用户已明确同意小型公开输入适配路线。以下替代被放弃的逐范围完整 state 候选；不删 PoC 失败历史，当前尚未生产编码。

### 模块与固定规则

新增一个局部输入事务模块，只读取当前 CM State 的文本邻域及 selection，以一次 `state.changeByRange` 生成一次 transaction；每个范围只生成 ChangeSpec 与 SelectionRange，不创建临时 EditorState、不重建 Markdown parser、不访问配对私有标记。不依赖 closeBrackets 私有来源状态，也不新增依赖。

固定输入集合 `(`、`[`、`{`、`'`、`"` 及对应闭合 `)`、`]`、`}`；无反引号、三引号或 Backspace 配对删除。范围处理顺序明确：

1. 非空范围遇开启括号或引号，以两端插入包裹，保留原选区方向和主范围；闭合括号则按普通输入替换范围。
2. 空光标输入引号，当前位置前连续反斜杠为奇数时只插入一个引号，不跳过、不创建配对；偶数视未转义。
3. 未转义引号或闭合括号与右侧字符相同，则仅把该范围光标前移，不修改正文，不要求本轮自动生成来源；纯跳过不产生正文 dirty/撤销步骤。
4. 其余开启括号仅在右侧为空、空白或固定闭合标点集合 `)]}:;>,` 时成对，否则普通插入。引号除满足该右侧条件外，左侧为 Unicode 字母/数字/下划线时按普通插入，避免英文词内撇号自动配对；不猜测 Markdown/编程语言字符串语义。相邻符号规则只作局部字符判断，单次最多读取当前连续反斜杠及邻近完整码点，不扫描全篇。
5. 其他情况普通输入替换该范围。同次混合跳过/转义/包裹/创建全部在同一 changeByRange，保持主范围、映射和单次历史；不逐光标 dispatch，不用整批 fallback 破坏其他范围规则。

规则覆盖已有普通闭合括号跳过及用户确认的已有引号/转义边界；若审查发现其与既有决策冲突，先报告，不自动扩大解析或产品语义。

### 公开输入接入与隔离

使用公开 `EditorView.inputHandler` 局部扩展，不全局监听字符键。仅单个允许 ASCII 输入且 `from/to` 与当前主范围一致时处理；否则返回 false 交原生输入（例如 replacement/autocorrect、非目标字符），不伪造 IME 事务。实际执行前确认 view 仍为该文档当前实例、活动文档与编辑/普通源码模式、无 safe/fault、无 readonly/frozen/busy、无 composition；沿现有 controller.updateEditor/history dispatcher 接收链，不绕过原文映射或保存权限。

被禁止的普通配对扩展不 dispatch；只读写入继续由 CM 与现有 controller 屏障拒绝。composition 期间不运行配对，原生候选输入仍由 CM 处理；不能拦候选 Escape/确认。安全源码不安装该配对行为，阅读没有 EditorView；离开/关闭后的旧回调不会改另一文档。扩展不增加命令、设置、RPC、日志或菜单，不改变已交付多选区快捷键。事务标注现有 `input.type`，沿已有 history，不强制破坏连续输入分组；独立一次配对在隔离编辑动作场景应可单步撤销。

生命周期：缓存 EditorState 只保留无 view/controller 捕获的纯输入扩展。实际 guard 通过模块私有 WeakMap 以当前 EditorView 为键在 MemoryEditor 创建时注册、销毁时删除；handler 以其实际入参 view 查询当次 guard，旧 view 无登记则不处理，不把旧 view 回调持久化到文档状态、不重开重复 append 扩展。guard 同时检查现有 inputBlocked 等输入屏障。规则不需要自建持久闭合标记或 StateField：已有同类闭合符按当前文本决定，不猜来源、不维护额外 map/undo 状态；非空包裹优先于空光标的转义规则。若必须改变此生命周期或引入状态跟踪，先重新报告。公开 inputHandler 的原生默认/insert 回调不用于绕过 composition；仅处理明确 from/to 匹配的目标单字符输入。

### 最小验证与确切预期

- 单范围：空文输入 `(` 得 `()` 且光标中间；选中 `中文` 输入 `[` 得 `[中文]`、原范围保持方向；`)` 前输入 `)` 原文不变只前移；`can't` 的撇号输入不额外配对。单双引号同类已有字符分别测试，奇/偶连续反斜杠给出确切正文与选区断言。
- 混合：原文 `"\n\\"\nAB\n`，四范围分别位于第一行引号前、第二行反斜杠后、反向选中 AB、最后空行，输入 `"` 后精确为 `"\n\\""\n"AB"\n""`；主范围和反向 AB 保持，只有一次目标 transaction，undo 恢复完整原文/redo 恢复结果。另外混合跳过闭合符与普通插入，不能整体退化。
- BOM/CRLF/LF、中文 emoji 码点边界与多范围未触及原始字节保持；输入模式切换/readonly/busy/frozen/IME/旧 view/from-to 不符覆盖真实生产 seam，不靠自造替代表达式。相邻或重叠范围遵循 CM 已规范化 selection，边界相邻插入纳回归。
- 1 MiB/多个范围仅记录有限操作成本与调用计数，证明单次目标 state 更新、不逐范围 parser/state 扩展推进；不设预期性能门槛或把单次时间当稳定 benchmark。
- 主线真实 WK 验证编辑/源码输入、混合多范围、范围包裹与跳过、词内撇号/转义、undo/redo、软换行/主题、safe/read/只读隔离、退出及磁盘未变；自然中文 IME 为必要实际验收，受控事件不能代替。离线仍留 F-043b-offline-final。
