# F-021h 在独立阅读窗口打开未保存快照

> 状态：alpha.275 已由 Agent 受托验收。

<!-- obligations: none -->
<!-- deferred-obligations: OBL-029 -->

## 功能说明

当前文档有未保存修改时，可以在独立阅读窗查看点击当时的正文。主窗保留原模式、选区、撤销历史和未保存状态。子窗标记「未保存快照」，关闭后可重开更新的版本。已保存文档沿用原入口和图片授权。

## 最小方案

- 主窗入口在点击时从当前编辑器的 `rawText` 捕获正文，保留 BOM、行尾和 Unicode。沿用文档状态、忙碌、冻结和输入法组合期间的操作限制。只在点击时编码，沿用 1 MiB 正文上限。
- 受信任的普通打包主窗负责选择当前编辑器的权威缓冲。Bun 验证未保存请求只有 `kind` 和规范 Base64 的 `data`，解码后必须为合法 UTF-8 且不超过 1 MiB。该分支只提供呈现，沿用单子窗、固定页面、沙盒、一次投递及退出保护。它不携带文件身份、授权或图片票据，也不调用文档服务。
- 子窗明确区分未保存正文与现有已保存两种载荷。主题、查找、代码复制和选区复制继续复用受控阅读视图。未保存快照的图片保留占位，打开或关闭子窗不会保存主窗或写入磁盘。主窗后续编辑或保存不会更新已经打开的快照。

## 最小验收

- 定向验证仅接受准确字段，拒绝无效 UTF-8、非规范 Base64、超限与混合图片票据。验证中文、emoji、BOM、CRLF 和类似脚本的字面文本保持原样。确认未保存分支不读取文件、不调用候选 Worker 或资产读取，第二次请求和迟到的窗口事件仍受单窗口限制。
- 在普通真实 WK 通过同一入口分别打开已保存和未保存夹具。已保存版仍可显示授权图片。编辑和源码模式中的未保存快照都显示点击时正文及标签，图片仍占位，正文只读。主窗再改一处后核对原子窗不变。关闭子窗后仍可撤销和继续编辑，核对磁盘摘要未变，退出保护仍生效。
- 实测恰好 1 MiB 的未保存正文从主窗 WK 经 Bun 到阅读窗 WK，核对首尾标记。自然中文候选期间核对入口被阻止，完成组合后核对实际已提交的正文。真实窗口与源码测试结果分别记录。
