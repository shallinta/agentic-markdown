## 1. 功能说明

- 将增量通道用于已有真实保存消费者，而非无消费者的每键后台同步。正常保存上传本次捕获正文相对已确认基线的局部差异；整篇替换时差异本身可能很大，不保证每次都更小或更快。
- 后台镜像是可重建的会话副本，不是磁盘基线、未保存正文权威或持久恢复数据。镜像失配时，拒绝错误 patch，再用此次保存捕获的 WebView 正文重建并最多重试一次；绝不以磁盘旧文覆盖当前编辑器。
- 外部磁盘变化仍拒绝覆盖；只读、通信失败、保存不确定等不当作镜像失配无限重试。保存期间新增编辑继续保持未保存，切换标签不串文档，不清除选区或撤销历史。
- 诊断显示最后传输方式与载荷大小，便于观察正常增量链路。故障与竞态以可控自动测试验证，不向产品增加故障注入按钮。
- 不实现即时排版、正式源码/阅读模式、解析缓存、自动保存、watcher、跨重启恢复或生产大文档放开。不宣称本轮消除全文扫描、hash 或本地字节转换的 O(N) 成本。

## 2. 最小技术方案

- 读取时在 Bun 建立有界、可驱逐的原文基线镜像，成功保存后推进镜像；释放授权或结束服务时清理。配额是当前实现安全边界，可按实测调整，不是冻结的性能指标。
- 新保存协议将磁盘 expected revision/hash 与镜像 token、buffer revision/hash 分离；patch 使用原始正文 UTF-16 坐标，计算边界不切断有效代理对，保持 BOM、混合 LF/CRLF 与未触及内容。
- 后台在原有保存串行化与授权范围内校验身份、版本、patch 范围、大小及目标 SHA-256；正确后仍使用原有 Node-API/Worker 原子写盘。不得因重同步跳过磁盘基线冲突检查。
- 成功回执返回元数据，不重复回传正文；前端验证回执并复用本次不可变保存快照更新磁盘基线，不替换最新 EditorState。请求与响应均有明确运行时校验。
- 无效/过期镜像仅返回绑定本次身份及磁盘基线的恢复信息，客户端最多一次以捕获正文重同步；迟到回执不得跨文档、关闭、重读或新生命周期提交。保存与关闭仍共用收尾保护。
- 迁移实际保存入口及既有测试，不保留生产绕过版本校验的旧全文入口。传输载荷数字明确计量口径，不等同网络实际字节或内存复制次数。

## 4. 最小 happy path 与必要边界

4. 保存未完成时继续编辑，完成后最新修改仍 dirty；验证身份/版本/哈希/范围/超限/无效回执、迟到、关闭/重读、权限、IME 与失败收尾，原安全链路不回退。

### 实际实现

- 新增 `shared/save-content.ts`、`bun/documents/buffer-mirror.ts` 与 `client/save-channel.ts`，真实保存 RPC 改用 patch/resync 内容联合类型；旧顶层全文 `text` 入口被拒绝。成功回执仅带元数据，客户端校验并复用捕获正文。
- 最近读取/保存初始化镜像；镜像最多保留 16 条，每条仍受 1 MiB 正文限制，恢复 token 同样有界。镜像可驱逐且不驱逐编辑器权威内容；释放句柄、重新读取与服务销毁使旧状态失效。
- patch 校验 token、基线 hash/revision、严格递增的目标 buffer revision、原始坐标及目标 hash。恢复 token 绑定文档身份、磁盘基线和目标正文/版本，仅允许一次恢复；磁盘探针保留 NOFOLLOW/NONBLOCK、授权/身份、大小、时间与 hash 校验。
- 传输前 hash 准备失败提示“尚未请求写盘”；已发送后的通信/无效回执仍保持保存不确定保护。原子写入与权限/关闭屏障继续复用 F-015a 路径。
- 既有诊断区增加“最近保存传输”，显示增量或权威全文重同步，以及该次请求 JSON UTF-8 应用载荷，不含底层协议开销；恢复场景显示最后一次全文请求，不是两次请求总和。
- `CONTEXT.md` 补充磁盘基线、保存捕获快照、会话镜像和镜像失配术语；新增 `scripts/create-f012b-fixtures.ts` 生成独立临时样本，不触碰工作文档。
