# Agentic Markdown 产品能力总账

> 版本：v0.1（2026-08-20）  
> 用途：把调研产品的功能与工程能力去重成“可单独决策”的原子项。它是决策台账，不是已批准 PRD。  
> 范围：桌面 App、网页版、开源项目、编辑器/渲染内核，以及为性能、安全、可靠性、发布与未来 Agentic 能力所需的非可见能力。

## 状态与阶段

- `已确认`：用户已明确给出方向。
- `建议`：调研后的初始判断，仍需用户确认。
- `待决策`：尚未讨论。
- `明确非 MVP`：能力可能保留，但用户已明确不纳入 MVP。
- 阶段候选：`M0`（编码前约束）、`MVP`、`v1`、`P1`、`Future`。

当前已经确认的基础结论：

1. 桌面框架基于 `shallinta/electrobun-app-starter`。
2. 核心产品价值是多 Markdown 文档的优雅查看与优雅编辑。
3. 性能是一等指标，而不是上线后的优化项。
4. Agentic 能力不进入 MVP。
5. MVP 与首个公开版本采用 macOS-first；其他平台保留适配边界，但不承诺同期发布。
6. 用户本地 Markdown 文件/文件夹是正文唯一真源；内部只保存可重建索引、缓存、会话和恢复数据。
7. 一个窗口采用多根目录模型：可加入多个任意文件夹和独立 Markdown 文件，它们作为同级顶层项共同组成窗口目录。
8. 文件树只展示 `.md` 文件以及包含 Markdown 后代的目录；无 Markdown 后代的目录分支和其他文件隐藏。
9. 同一个 Markdown 文件在窗口目录中只能出现一次；独立文件被后来加入的目录覆盖时，自动移除其顶层叶子身份。
10. 文件夹根之间按规范化路径的包含关系自动去重，只保留最外层目录根。
11. 每个窗口的顶层文件夹/独立文件集合自动保存并在启动时恢复；不向用户目录写入私有 workspace 配置文件。
12. MVP 只提供一个主窗口；多窗口延后到 P1，所有系统打开请求汇入主窗口。
13. 已正式打开的 Markdown 文档以持久标签页承载，同一路径只有一个标签；标签状态与顺序随会话恢复。
14. 单击文件树使用唯一临时预览标签；双击、编辑、固定或拖入分栏后转为持久标签。
15. MVP 采用主副分栏：主区持有标签，副区无标签并平铺全部文档；不实现任意递归分栏。
16. 副区域不使用整体滚动；全部副区文档始终压缩在当前副区域视口内，并按可调比例分配空间。
17. 副区无固定篇数上限；容量由平铺轴长度动态决定，每篇至少保留标题栏与相邻分隔线，窗口缩放不得突破现有文档的总最低占位。
18. 主副区域固定为左右布局，副区文档固定从上到下平铺；不提供上下主副布局。
19. 副区满载时不关闭、不替换现有文档；显式拖入失败，双击打开则降级到主区持久标签并提示。
20. 主区域固定在左，副区域固定在右；MVP 不支持交换两者位置。
21. 副区无文档时自动收起，也可在有文档时手动收起；只能手动展开并恢复上次宽度，收起态不接受拖入或双击路由。
22. 收起副区会把活动区域切回主区；双击继续在主区打开，直至副区重新展开并被激活。
23. 用户手动展开副区后，副区立即成为活动区域；展开动作本身不打开或移动文档。
24. 副区首次展开占主副内容总宽度的 35%；之后恢复用户上次调整比例，并在当前窗口合法范围内约束。
25. 主区域与副区域的结构性最小宽度均为 160px，主副分隔线和窗口缩放不得突破。
26. 新文档默认追加到副区底部；旧文档先按比例缩小并钳制到最低高度；若新文档剩余不足最低高度，再由仍有余量的旧文档均摊让位，全部触底后仍不足才原子失败。
27. 副区文档可通过拖动标题栏重新排序；每篇文档携带自己的高度移动，其他文档不重新分配高度。
28. 副区标题栏仅显示文件身份、dirty 状态、移入主区和关闭操作；其余区域作为排序/跨区拖动热区。
29. 副区标题栏 32px、可见分隔线 1px，文档最低占位 33px；分隔线拖动命中区为 3px 且不额外占布局高度。
30. 拖动副区文档分隔线只调整直接相邻两篇文档；任一达到 33px 后停止，不向其他文档连锁传递。
31. 副区文档离开时，其全部高度优先交给下方相邻文档；若无下方则交给上方；其他文档高度不变。
32. 副区文档是完整文档区域，可在原位置直接进入编辑模式，无需先移入主区。
33. 文档采用阅读、编辑、源码三种状态；“编辑模式”特指直接编辑原文的即时预览/WYSIWYM，源码是高级精确编辑与故障降级入口。
34. 阅读模式使用统一的主题包模型；随 App 分发和后续安装的主题在能力与界面上不分类。
35. 阅读主题是窗口级全局设置，统一作用于主区和副区阅读文档；不按文档分别保存。
36. MVP 只提供随 App 分发的 ThemePackage 切换；外部主题安装、自定义与第三方主题统一延后到 P1。
37. 产品永久不提供以富文本树为编辑模型并重新序列化 Markdown 的完整 WYSIWYG 模式。
38. 产品永久不提供同一文档源码与 canonical 阅读预览并排的分屏模式。
39. 所有正式打开的 Markdown 文档默认进入编辑模式；只有文件树单击产生的临时预览使用阅读模式。
40. 临时阅读预览转为持久文档时保留阅读模式，不因固定、拖动或持久化身份变化而自动进入编辑。
41. 持久打开前按 canonical path 查询主区、副区与临时预览；已存在则激活原实例并保持模式，不存在才创建默认编辑模式实例。
42. 阅读、编辑和源码模式都是文档级状态，每篇主区或副区文档可独立切换，不存在窗口统一模式。
43. 主区标签只显示文件身份、dirty 与关闭；当前主区文档通过右上角悬浮工具栏显示和切换模式；副区在各自标题栏切换。
44. 主区悬浮工具栏只有一个无文本图标，切换阅读/编辑；默认整体半透明，悬停转为半透明毛玻璃/可用时液态玻璃，并以 tooltip 描述目标模式。
45. 源码模式不提供可见按钮、菜单或命令入口，只能通过快捷键切换。
46. 源码快捷键再次触发时返回该文档进入源码前的阅读或编辑模式；源码态隐藏阅读/编辑 toggle。
47. 会话恢复逐文档恢复阅读、编辑或源码模式；源码状态同时恢复其退出后应返回的前置模式。
48. 文档切换模式时优先保持当前可见 Markdown 内容块及其相对屏幕位置；块锚点失效时才逐级降级到邻近块、源码位置或滚动比例。
49. `⌘F` 在阅读、编辑和源码三种模式下都查找当前活动文档；该入口不承担多文档或工作区全文检索。
50. 阅读模式与编辑模式的文内查找以用户可见正文为匹配对象；源码模式查找完整 Markdown 原文，因此切换模式后结果数量允许发生变化。
51. MVP 文内查找支持普通文本、区分大小写和全词匹配，不支持正则表达式；正则查找延后评估。
52. 查找栏和查询状态属于具体文档；主区标签与副区文档可分别保持各自的查找词、匹配选项、当前结果和打开/关闭状态。
53. 查找栏悬浮在对应文档正文右上角，不占布局高度；正文右上角已有模式切换按钮时，查找栏位于其左侧；正文被压缩到不足以显示查找栏时允许其被裁掉。
54. 同一文档切换阅读、编辑或源码模式时保留查找词、大小写和全词选项；切换后按目标模式的文本语义重新计算，并选择最接近当前内容锚点的匹配项。
55. 文内查找计算全文匹配总数，但只为当前渲染视口及缓冲区创建普通高亮；当前匹配项单独强调，跳转后按需生成目标区域高亮。
56. 基于 Markdown 标题层级生成、可点击定位的大纲纳入 MVP；阅读、编辑和源码三种模式复用同一份增量解析元数据，不为大纲重复解析全文。
57. 大纲的具体呈现方式以及是否跟随当前位置暂缓，等待主区工具栏、副区标题栏、文档内空间与 160px 极限宽度一起完成视觉原型后再决定。
58. 标题章节折叠纳入 MVP，并同时支持阅读模式和编辑模式；折叠只影响当前展示，范围状态不写入 Markdown 原文。
59. 阅读、编辑和源码三种模式共享同一套文档级标题折叠状态；切换模式保持折叠结果，定位目标落入折叠范围时自动展开必要祖先。
60. 标题左侧边缘使用独立小箭头控制章节折叠；展开时仅在标题悬停或键盘聚焦时出现，收起时常显，不占用标题文本的点击与选择语义。
61. 同文档锚点和本地 Markdown 链接在 App 内导航，`http/https` 链接交给系统默认浏览器；新打开的本地 Markdown 链接目标以主区临时预览标签承载。
62. 链接目标尚未属于窗口文件树时，临时预览不自动加入文件树；用户主动将其转为常驻时询问是否加入，确认后作为独立文件根加入并常驻，取消后保持临时预览。
63. 文件树单击与本地 Markdown 链接复用全窗口唯一临时预览标签；新预览替换该槽位内容，同路径已有正式实例时直接激活既有实例而不创建副本。
64. 临时预览中的连续本地 Markdown 链接跳转维护前进/后退历史；从文件树单击新的预览文档时开始新链并清空旧历史。
65. 未加入文件树的链接预览在切换编辑/源码、实际输入、固定或拖入副区等常驻操作前统一询问；确认后加入独立文件根并继续，取消后取消原操作且保持阅读预览。若实测阻力过大，可后续重评“编辑时自动加入”。
66. 阅读模式单击链接即激活；编辑与源码模式使用 `⌘ + 点击`激活，普通点击保留给光标定位、选择和修改链接文本。
67. 不提供 Hover 链接内容预览；本地 Markdown 链接通过主区临时预览或既有正式实例查看，不维护悬停渲染卡片。
68. 仅为当前打开的正式文档保存稳定内容块锚点与视口偏移，并随会话在重启后恢复；临时预览不持久化该状态，显式关闭标签后立即删除；正文变化时按邻近块、源码位置、滚动比例逐级校正。
69. MVP 不显示阅读百分比或专用进度条，只使用滚动条与位置恢复；可见阅读进度保留为后续版本候选。
70. 字数、字符数和预计阅读时间均不进入 MVP，统一保留为后续版本候选。
71. MVP 的正文缩放只作用于主区域，并统一影响主区文档的阅读、编辑和源码模式；副区域始终使用基准字号，不继承主区比例。
72. 当前活动文档位于副区时，`⌘+`、`⌘-`、`⌘0`静默无效；不提示，也不在后台改变主区缩放比例。
73. 系统打印与打印样式不进入 MVP，延后到 P1，并与 PDF 输出能力统一设计。
74. 阅读模式的自研块级虚拟化不进入 MVP，具体渲染优化方案暂不决定；后续根据真实性能数据重新评估。编辑与源码继续使用 CodeMirror 6 自带视口渲染，不属于该延期项。
75. MVP 最终支持的 Mermaid、KaTeX、大型代码高亮等重型块必须在接近视口时才加载运行时并渲染；视口外使用轻量占位，离开后不强制立即销毁。
76. Markdown 高亮与标记显隐参考 Typora：编辑模式优先展示排版语义，非活动标记智能隐藏，光标或选区进入元素时显露必要源码；源码模式完整显示 Markdown 语法高亮；代码围栏按声明语言独立高亮。
77. 源码模式默认显示逻辑行号；软换行的视觉续行不重复编号。阅读与编辑模式不显示行号。
78. 仅源码模式轻量高亮光标所在逻辑行及对应行号；软换行部分属于同一逻辑行共同高亮，编辑模式不显示整行底色。
79. 编辑与源码模式都启用括号、方括号、花括号和单双引号的上下文感知配对；支持选区包裹、跳过已有闭合符、IME composition 避让与单步撤销。
80. MVP 采用保守的 Markdown 情境补全：只在意图明确时补齐链接、行内代码、强调和代码围栏；普通 `*`、`_`、`-` 输入不做激进结构推断。
81. 编辑与源码模式都支持列表自动续写：有序列表递增、任务新项默认未完成、保留嵌套与无序标记；空项回车退出，`Shift+Enter`只换行。
82. 编辑与源码模式的 `Tab / Shift+Tab`采用 Markdown 结构感知缩进：列表项连同子项变更层级，引用增减层级，代码围栏只处理内容，多行选区整体操作。
83. 普通段落没有合法 Markdown 缩进目标时，`Tab / Shift+Tab`由编辑器消费并保持焦点，但不修改内容；不插入制表符，也不移动到其他 UI 控件。
84. MVP 仅在源码模式启用 CodeMirror 6 原生多光标与多选区；编辑模式保持单光标，多光标编辑模式留作后续评估。
85. 产品不提供矩形/列选择；源码模式保留普通多光标、多选区和连续多行选区。
86. MVP 在编辑与源码模式提供当前文档逐项替换和全部替换；阅读模式只查找。编辑按可见文本映射原文范围，源码直接替换原文；全部替换是一个撤销事务。
87. 每篇正式打开文档维护独立撤销栈，编辑与源码模式共享；保存、切换、跨区移动不清空，明确关闭标签或 App 重启后不恢复历史。
88. 围栏代码块在阅读、编辑、源码三种模式中均可折叠并共享文档级状态；折叠摘要保留语言与行数，定位进入隐藏代码时自动展开。
89. 阅读与编辑模式正文始终随容器换行；源码模式默认开启软换行，并提供全局关闭选项，关闭后超长逻辑行使用横向滚动。围栏代码块内部换行策略另行决定。
90. MVP 使用操作系统拼写检查：编辑模式默认开启；源码模式默认关闭但可独立开启；阅读模式不检查。优先检查自然语言文本并避开代码、链接目标和 Markdown 标记，不内置独立词典或校对引擎。
91. MVP 不提供语法与文风检查；未来可作为用户主动触发的可选 Agentic 校对能力评估，不允许默认常驻后台分析或阻塞编辑链路。
92. Focus Mode 放入 P1：目标是主动开启后降低非当前写作范围的视觉权重；聚焦粒度、适用文档模式和控制入口留到 P1 设计时确定，MVP 不实现。
93. Typewriter Mode 放入 P1，与 Focus Mode 使用独立开关且允许组合；目标是持续输入时让光标尽量保持在固定垂直区域，具体锚点、滚动动画和适用模式留待 P1 设计。
94. Hemingway Mode 放入 P1，以 ghostwriter 禁用 `Backspace/Delete` 的轻量行为作为参考基线；是否进一步限制剪切、替换或光标移动必须在 P1 设计时单独确认，MVP 不实现。
95. Vim 模态键位放入 P1，仅在源码模式提供；通过 CodeMirror 6 Vim 扩展按需加载，未启用时不得进入初始包与普通编辑热路径，编辑模式不支持。
96. 格式入口采用 Typora 式分层：MVP 以 Markdown 直接输入、快捷键和菜单为主，并仅为确有需要的复杂结构提供情境控件；P1 增加默认关闭、可选启用的浮动格式工具栏。所有入口复用同一命令与文本 transaction，不维护富文本副本。
97. MVP 提供命令面板与统一命令注册表；菜单、快捷键和命令面板引用同一命令定义，面板支持名称搜索、快捷键展示与键盘执行，并根据当前模式、区域、文档与选区过滤或标示可用性。
98. Slash 命令放入 P1：仅在编辑模式的空白行或行首上下文触发，复用统一命令注册表；它只是命令入口，执行结果仍是标准 Markdown 文本，不引入块数据库或专有文档模型。
99. 自定义快捷键放入 P1；MVP 使用固定的 macOS 默认映射，P1 基于统一命令注册表提供修改、清除、恢复默认与冲突检测，并保护系统保留组合键。
100. MVP 支持富文本智能粘贴：编辑模式普通粘贴优先将清理后的 HTML 语义转换为 Markdown，`⌘⇧V` 强制使用纯文本；源码模式普通粘贴始终使用纯文本。脚本、事件属性和纯视觉样式不进入文档，转换作为一个可撤销 transaction。
101. MVP 支持从 Finder 拖入图片文件和从剪贴板粘贴位图：将图片复制到文档附近的本地资产目录并插入相对 Markdown 图片链接；未保存文档必须先保存。
102. 图片资产默认存入 Markdown 文档同目录下共享的 `./assets/`，并允许配置资产目录模板；同名文件生成安全后缀且绝不覆盖已有文件。
103. App 不提供图片资产清理能力：不因删除引用、关闭标签、删除文档或扫描结果而自动删除资产，也不提供“清理未引用资产”命令；资产文件完全由用户或外部工具管理。
104. 表格编辑参考 Typora：MVP 在编辑模式直接呈现并编辑 GFM 表格单元格，提供情境工具栏完成增删行列、调整规模和列对齐，并支持键盘移动；源码模式保留原始 Markdown。拖动重排行列放入 P1；不支持合并、多行单元格、筛选、排序或公式。
105. 链接编辑采用 Typora 式原地展开：编辑模式中光标进入链接时显露其 Markdown 标记并直接编辑，离开后恢复排版显示，不提供字段化编辑弹层；引用式链接保持引用结构并提供跳转到定义，源码模式始终显示原文。
106. Markdown 文档/选区格式化放入 P1：仅由用户显式触发，执行前展示差异预览，应用后作为一个撤销事务；保存流程永不自动格式化，也不以“语义等价”为由静默改写原始排版。
107. CJK IME 完整支持是 MVP 发布门禁：编辑与源码模式必须正确处理中文、日文、韩文 composition；候选确认前不执行会干扰输入的 Markdown 补全、自动配对、装饰切换或预览同步，确认后统一更新并保持合理的撤销边界。
108. RTL 与双向文本完整支持放入 Future：MVP 和 P1 不承诺阿拉伯语、希伯来语及复杂 bidi 混排体验，也不设置专项门禁；基础实现避免无必要地固化纯 LTR 假设。
109. M0 固定 CommonMark 规范版本与一致性测试 corpus，作为所有模式和扩展的共同语义基线；允许编辑增量解析、阅读渲染等场景使用不同实现，但必须共享方言配置并通过结构边界一致性测试。此前确认的 GFM 表格作为 MVP 扩展叠加在该基线上。
110. MVP 支持 GFM 任务列表；仅编辑模式中的复选框可点击并精确写回 `[ ]`/`[x]`，阅读模式对正式文档和临时预览都严格只读，源码模式只提供原文编辑。点击切换进入文档统一撤销历史。
111. MVP 支持 GFM 删除线，但采用明确的 Typora 兼容例外：仅 `~~text~~` 表示删除线，单个 `~text~` 保留给下标；阅读与编辑模式呈现删除线，编辑模式按光标位置显隐标记，源码模式显示原文。
112. GFM 作为一个完整、内置、可版本化的 `GFMExtension` 能力包叠加到 CommonMark 核心，而非若干独立语法开关；扩展包统一贡献表格、任务列表、删除线、扩展自动链接和 tagfilter 的解析、渲染、编辑、索引与测试能力。App 固定一个包含“仅双波浪线删除线”例外的兼容性 profile；该首方扩展边界不等同于 MVP 对第三方开放通用插件 API。
113. MVP 始终启用完整 `GFMExtension`，不提供全局关闭或逐文档方言选择；模块边界用于首方隔离、版本固定、一致性测试和未来增加其他扩展，而非向用户暴露 GFM 子功能开关。
114. YAML Frontmatter 由原子 `FrontmatterExtension` 提供并加入 `ExtendedMarkdownPreset`：只识别文档开头合法边界，原文保真，编辑模式提供可折叠原始 YAML 区块，源码模式显示完整原文；解析错误只在区块上提示且不阻塞正文。阅读模式的呈现方式暂缓决定。
115. 不提供 Properties 可视化编辑；Frontmatter 在编辑和源码模式中始终以 YAML 原文操作，不建立类型化表单状态，也不承担表单与注释、锚点、引号及排版之间的双向同步。
116. 引用式脚注由原子 `FootnoteExtension` 提供并加入 `ExtendedMarkdownPreset`：支持 `[^id]` 引用和定义，阅读模式显示上标并提供脚注与正文往返，编辑模式按需显露标记，源码模式显示原文；不支持 Pandoc 行内脚注。
117. 定义列表由原子 `DefinitionListExtension` 提供并加入 `ExtendedMarkdownPreset`：支持“术语行 + 以冒号开头的定义”并渲染为语义化 definition list；编辑模式按需显露结构标记，源码模式保留原文，解析与渲染使用固定兼容性 corpus。
118. MVP 采用 Typora 风格下标 `~text~`；为消除语法冲突，`GFMExtension` 的删除线只接受 `~~text~~`。这是对官方 GFM 单波浪线删除线规则的显式、固定偏离，必须由解析优先级、兼容性文档和回归 corpus 共同约束。
119. 上标与下标由原子 `SubSupExtension` 提供并加入 `ExtendedMarkdownPreset`：`~text~` 表示下标、`^text^` 表示上标；阅读与编辑模式呈现语义样式，编辑模式按焦点显隐标记，源码模式显示原文。`GFMExtension` 只注册 `~~text~~` 删除线，不再注册单波浪线规则。
120. MVP 由原子 `HighlightExtension` 支持 `==text==` 高亮并加入 `ExtendedMarkdownPreset`；阅读与编辑模式呈现高亮，编辑模式按焦点显隐标记，源码模式显示原文；具体颜色由主题决定，不写入 Markdown。
121. App 的固定 Markdown 方言命名为 `ExtendedMarkdownPreset`。它组合 `CommonMarkCore`、`GFMExtension` 与所有逐项确认的原子 Extension；MVP 始终使用该 Preset，不提供方言切换。Preset 只声明组合、版本和优先级，原子 Extension 各自负责解析、渲染、编辑、索引、测试与按需加载，避免形成巨型插件。
122. Emoji shortcode 由原子 `EmojiExtension` 提供并加入 `ExtendedMarkdownPreset`：支持固定版本的 `:name:` 映射，阅读与编辑模式呈现 Emoji，源码和磁盘原文始终保留 shortcode；编辑模式只在合法上下文中按需加载并显示候选，只有满足词法边界的已知 shortcode 才解析，避免把时间、URL 等普通冒号文本误识别为 Emoji。
123. 数学公式由原子 `MathExtension` 提供并加入 `ExtendedMarkdownPreset`：MVP 支持 `$...$` 行内公式和 `$$...$$` 块公式，使用 KaTeX 的受支持语法子集；仅在文档包含公式时加载渲染能力，并按视口渲染块公式。阅读与编辑模式呈现公式，编辑模式聚焦公式时显露原始标记，源码模式始终显示原文；解析或渲染失败只在原位置显示可编辑的源码与局部错误提示，不阻塞文档。美元符号识别采用严格边界，避免把普通金额误判为公式。
124. Mermaid 由原子 `MermaidExtension` 提供并加入 `ExtendedMarkdownPreset`：MVP 将语言标识为 `mermaid` 的 fenced code block 渲染为图表；只有文档包含 Mermaid 且图表接近视口时才加载和执行渲染。渲染采用严格安全配置、可取消任务与时间预算，生成的 SVG 经净化后再展示；阅读与编辑模式显示图表，编辑模式聚焦图表时显露源码，源码模式显示原始围栏。解析、超时或渲染失败只使当前块降级为可编辑源码和局部错误提示，不影响文档其余部分。
125. MVP 的内置图表渲染范围仅包含 Mermaid；Graphviz、ECharts、PlantUML 不进入 MVP，也不作为同一个图表包的隐藏依赖。它们保留为 P1/Future 的独立原子 Extension 候选，后续分别评估本地运行依赖、安全、包体与性能后再决定；当前无法识别或未安装渲染器的 fenced block 必须原文保真，并按普通代码块显示。
126. fenced code block 的编辑体验参考 Typora：输入围栏及可选语言后确认即可转换为独立代码编辑块；编辑模式中不显示开始与结束围栏，即使聚焦也直接编辑代码内容，并在代码块右下角提供语言输入控件。该控件只修改 info string 的语言标识部分，未识别的其余 info string、原始围栏字符与长度必须保真，完整内容可在源码模式编辑。阅读模式只显示排版后的代码块，源码模式显示原文；未知语言仍按纯文本代码块展示，代码永不执行。这里参考 Typora 的交互效果，不采用其“只支持 fenced code block”的语法限制，CommonMark 缩进代码块仍按基线解析。
127. MVP 提供较完整的常用代码语言高亮目录，但每种语言 grammar 必须独立分包：只有文档实际使用该语言且代码块接近视口时才加载，加载后在窗口级缓存复用。语言注册表固定版本并统一处理 `js`、`ts`、`sh`、`yml` 等常见别名；未知或加载失败的语言立即降级为纯文本，不阻塞编辑，也不通过网络下载 grammar。语法 token 的颜色由当前文档主题提供，高亮结果不写回 Markdown。
128. 代码块解析与高亮采用 CodeMirror 6 + Lezer 单一开源技术栈，不引入 Shiki、Prism、highlight.js 或 React 代码块组件作为第二套常驻高亮系统。编辑模式复用 Markdown 编辑器的嵌套语言解析，不为每个代码块创建独立 `EditorView`；语言注册表通过 `LanguageDescription` 异步加载 grammar。阅读模式复用同一语言 parser，并通过 Lezer `highlightCode`/`highlightTree` 生成静态安全 DOM；两种模式共享语言别名、grammar 缓存与主题 token。App 只自研代码块外壳、语言控件、复制入口和错误降级。
129. MVP 为代码块提供显式复制入口：阅读模式下，代码块 hover 或键盘聚焦时在右上角显示可访问的复制按钮，只复制代码正文，不包含围栏、语言标识或行号；成功后短暂显示“已复制”，失败则给出可恢复提示。编辑模式不叠加悬浮按钮，以免干扰光标和选区，但右键菜单提供“复制代码块内容”；源码模式沿用普通选区复制。所有入口使用同一纯文本复制服务，不修改文档或撤销历史。
130. MVP 的代码块行号参考 Typora，作为全局展示偏好提供且默认关闭；开启后编辑模式和阅读模式中的 fenced code block 同步显示行号。行号是不可选中的虚拟 gutter，不进入复制内容、搜索文本、Markdown 原文或撤销历史；切换偏好即时重绘，不重新解析或改写文档。该设置与源码模式编辑器自身的行号偏好相互独立。
131. 持久化代码高亮行放入 P1，采用 fenced info string 中的 `{1,3-5}` 语法表示单行与闭区间；编辑和阅读模式以主题定义的背景强调对应行，复制内容不包含元数据。MVP 只保证这类 info string 原文保真，不解释或改写它。P1 实现时，非法、重复、倒序或越界范围均忽略但保留原文，不得使代码块解析失败；具体编辑入口后续设计，源码模式始终可直接修改完整 info string。
132. MVP 对 CommonMark 原始 HTML 采取“原文保真 + 安全子集渲染”：解析层始终保留原始 HTML；阅读模式只插入净化后的安全 DOM，编辑模式对安全行内标签直接呈现并在聚焦时显露源码，对 HTML 块则失焦预览、聚焦编辑源码，源码模式始终显示原文。`script`、`style`、`iframe`、`object`、`embed`、表单、事件属性、可执行 URL 与其他不在 allowlist 中的结构永不执行或进入活动 DOM，而是在原位置以不可执行源码和原因提示展示，不能静默删除。HTML 渲染内容不得访问 App RPC 或扩大本地文件权限；MVP 不提供“受信任文档”绕过净化的开关。
133. Callout 由原子 `CalloutExtension` 提供并加入 `ExtendedMarkdownPreset`：MVP 只支持 GitHub Alert 兼容的 `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION` 五种 blockquote 标记。阅读与编辑模式按主题呈现固定语义图标、标题和样式，编辑模式聚焦时显露必要标记，源码模式显示原文；未知类型保持原文并退化为普通 blockquote。MVP 不支持自定义标题、`+`/`-` 折叠状态、自定义类型或 Callout 嵌套，不引入 Obsidian 完整方言。
134. Wikilink 由原子 `WikilinkExtension` 提供并计划在 P1 加入 `ExtendedMarkdownPreset`，支持 `[[文档]]`、`[[路径/文档]]` 与 `[[文档|显示文本]]`。解析范围仅限当前窗口统一文件集合中的目录根与独立文件：无路径链接先匹配源文档同目录，否则仅在全窗口 stem 唯一时解析；带路径链接先按源文档目录相对路径匹配，再按各顶层目录根匹配；多个候选必须由用户选择，绝不静默绑定。未找到时显示未解析状态且不自动创建文件；点击已解析链接沿用本地 Markdown 链接规则，在主区以预览标签打开。P1 首版不因文件重命名自动重写 Wikilink，但索引必须保留未解析与歧义状态，供后续修复与 Backlink 能力复用。
135. Block ID 与块引用由原子 `BlockReferenceExtension` 提供并计划在 P1 加入 `ExtendedMarkdownPreset`，依赖 `WikilinkExtension` 的文档解析：支持在段落或列表项末尾写入 `^block-id`，并通过 `[[文档#^block-id]]` 或 `[[#^block-id]]` 精确跳转。App 不为所有内容自动生成 ID；只有用户执行“复制块链接”或“创建块引用”且目标尚无 ID 时才写入，手工输入的合法 ID 同样识别。ID 必须在单篇文档内唯一，重复、不存在或目标文档歧义时标记为未解析，绝不静默选择。首版不支持 Logseq `((uuid))`、复杂结构块 ID 或内容嵌入；内部视口恢复锚点仍是独立会话数据，永不因此写入 Markdown。
136. 内容嵌入由独立 `TransclusionExtension` 保留到 Future，待 P1 的 `WikilinkExtension`、`BlockReferenceExtension` 与链接索引稳定后再实现；语法候选为 `![[文档]]`、`![[文档#标题]]`、`![[文档#^block-id]]`。嵌入内容在阅读与编辑模式中始终只读，点击可打开源文档，源码模式显示原始链接；接近视口时才解析和渲染。实现必须维护文档/章节/块级依赖图与缓存，源内容变化时局部失效；循环、超出深度预算、歧义或目标缺失均在原位置显式降级，不阻塞宿主文档。MVP 与 P1 仅保真该语法，不渲染嵌入。
137. 学术引用管理由独立 `CitationExtension` 保留到 Future；MVP 与 P1 仅原文保真，不解释 Pandoc Citation。Future 第一阶段支持 `[@key]` 等 Pandoc Citation、本地 Frontmatter 声明的 BibTeX/BibLaTeX 或 CSL JSON/YAML bibliography，以及本地 CSL 样式；编辑模式提供 citation key 补全，阅读模式按需生成引用文本与参考文献表。缺失、重复或无效 key 显式提示但不改写原文。首阶段不建立 App 私有文献数据库，也不绑定 Zotero 同步、联网检索或附件管理；这些能力继续独立后置。
138. TOC 由原子 `TocExtension` 提供并加入 `ExtendedMarkdownPreset`：MVP 将单独一行、大小写不敏感的 `[TOC]` 识别为目录占位符，同时完整保留用户原始大小写。编辑与阅读模式在该位置动态呈现 H1–H6 层级目录，复用文档标题索引与锚点，标题变化时增量更新，点击条目跳转到对应标题；源码模式显示原指令。生成结果永不写回 Markdown，也不参与正文搜索或字数统计；不满足独立行边界的 `[TOC]` 按普通文本处理。
139. App 不支持 MDX/JSX 语义，也永不解析或执行其中的 JavaScript。`.mdx` 不进入目录递归加载结果；用户显式单文件打开 `.mdx` 时，仅以源码模式作为普通文本查看和编辑，不提供编辑/阅读渲染模式。`.md` 中出现的 JSX、`import`、`export` 或 `{expression}` 不执行、不解析为组件；其中符合 CommonMark 原始 HTML 节点的部分仍受已确认的安全 HTML allowlist 与净化规则约束，其余保持普通文本。MVP、P1 与 Future 均不规划 MDX 组件运行时或“受信任执行”开关。
140. MVP 对未知语言或自定义类型的 fenced block 采用无损降级：精确保留原始围栏字符与长度、完整 info string 和正文；编辑模式按普通代码块直接编辑并显示原始类型名称，阅读模式按普通代码块展示，源码模式显示完整原文。内部处理器注册表只在已启用的首方原子 Extension 明确声明首个 info token 时接管渲染；无处理器时不报错、不执行、不联网查找插件。未来 Extension 可在不迁移或改写文档的前提下接管既有类型，但这不代表 MVP 开放第三方插件 API。
141. MVP 完整呈现标准 Markdown 图片：编辑模式显示图片，点击时显露并可编辑 alt、路径与 title 源码；阅读模式只显示图片，源码模式显示原文。相对路径严格以源 Markdown 文件目录为基准解析，支持 `../`，但不跨目录或多个顶层根猜测同名文件。图片接近视口时才加载和解码，离屏解码资源受独立图片缓存配额管理；展示保持宽高比并受正文最大宽度约束，具体尺寸/对齐方言留给 S-32。加载失败在原位置显示含 alt 与路径的明确占位；SVG 仅作为惰性图片资源加载，绝不以内联活动 DOM 执行。远程图片是否发起网络请求由独立隐私策略决定。
142. 音频与视频内嵌播放放入 P1，通过安全 HTML allowlist 支持 `<audio>` 与带 `controls` 的 `<video>`，不新增 Markdown 方言。编辑模式和阅读模式使用平台原生媒体控件，源码模式显示原文；禁止自动播放，忽略或移除 `autoplay`，相对地址严格以源 Markdown 文件目录为基准解析。媒体接近视口时才创建和加载，离屏、文档标签隐藏或关闭时必须暂停并释放重资源；文件缺失、格式或编解码器不受支持时在原位置显示明确占位。远程媒体是否发起请求继续服从独立隐私策略。MVP 阶段不将 `<audio>`、`<video>` 纳入活动 HTML allowlist，只保留并以不可执行源码呈现。
143. 当前路线不提供 App 内 PDF 预览或正文 PDF 嵌入，不建设 PDF 查看器，也不新增 PDF 专用 Markdown 方言或放开 `iframe`、`object`、`embed`。Markdown 中的本地 PDF 保持为普通文件链接，点击后交给系统默认应用打开；远程 PDF 沿用外部网页链接行为。PDF 路径和任何尚未识别的嵌入写法均原文保真。该能力不排除未来重新评估，但目前不进入 MVP、P1 或已承诺的 Future 范围。
144. 当前路线不提供正文网页或 iframe 嵌入：`iframe`、`object`、`embed` 及等价的活动网页容器始终保持为不可执行源码并显示安全原因，不进入活动 DOM；App 不新增网页嵌入方言、站点白名单或“受信任文档”绕过。普通网页链接点击后交给系统浏览器打开。该决定同时避免外部脚本获得长驻执行环境、隐式网络请求、后台耗电、布局抖动以及对本地内容和 App RPC 的权限探测；目前不进入 MVP、P1 或已承诺的 Future 范围。
145. 图片尺寸能力参考 Typora 放入 P1，不新增 Markdown 图片方言：标准 `![alt](src)` 始终保持标准语义、等比缩放并受正文最大宽度约束；图片独占一个段落时默认居中，行内图片跟随文本流，不提供持久化左对齐或右对齐语法。P1 的安全 HTML `img` allowlist 允许以 `width`、`height` 和严格受限的 `style="zoom:..."` 表达显式尺寸，非法值、其他 CSS 或危险属性不进入渲染 DOM，但原始 HTML 仍完整保留。显式宽高缺省时保持宽高比并继续受容器限宽。P1 暂不提供拖拽缩放，尺寸通过源码修改；不兼容 MWeb 的 alt 后缀或另增属性列表语法。
146. MVP 提供独立的 Quick Open 文件快速打开器，默认快捷键为 `⌘P`。搜索范围严格等于当前窗口统一文件集合中的所有目录根和顶层独立 Markdown 文件，不扫描未加入窗口的路径；仅基于文件名与展示路径的元数据做增量模糊匹配，不读取正文或依赖全文索引。结果展示文件名、所属顶层根及可区分的路径，支持完整键盘导航和虚拟化长列表；排序依次考虑精确匹配、前缀匹配、模糊匹配质量，并以最近打开记录打破同分。`Enter` 将文档作为持久标签打开到最后激活区域，并复用既有绝对路径去重、副区收起和满载降级规则；已打开的文档只激活原位置并保持原模式。
147. MVP 提供跨当前窗口统一 Markdown 文件集合的全文搜索，采用可删除重建的本地持久化增量索引；索引缓存以规范化绝对路径和文件元数据/内容版本为键，绝不是内容真源，也不上传网络。独立索引工作单元在窗口首屏之外运行：启动时立即使用可用旧索引并异步核验，保存操作与文件系统事件触发单文件更新，索引未就绪或更新中必须显示状态而非阻塞 UI。打开文档的未保存内容作为内存覆盖层参与查询，并屏蔽该文件的过期磁盘命中。每次新查询取消前一查询，结果以虚拟化列表流式返回并按文件分组展示上下文片段。CJK 分词、索引体积、构建速度与查询延迟必须用真实中文/英文/混合语料基准测试；SQLite FTS5、Tantivy 或其他后端由性能 PoC 决定，不在产品规格中预锁实现。
148. 搜索筛选分阶段提供。MVP 的全文搜索支持可组合的 `root:`、`path:`、`-path:` 与 `file:` token，分别限定顶层目录根、包含路径、排除路径和文件名；所有筛选只作用于当前窗口已加入且已按绝对路径去重的 Markdown 文件集合，不扩大扫描范围。搜索栏旁的筛选入口生成并回显同一组可编辑 token，直接键入与 UI 选择共享一种解析和查询状态；含空格的值可引用，非法或歧义 token 必须原位提示，不能静默当作正文关键词。多个同名顶层根由内部稳定 root ID 区分，并在 UI 中显示足够路径。`tag:`、`property:` 与 `modified:` 等筛选放入 P1，分别等待标签、Frontmatter 真源和日期语义确定后再加入；MVP 不提供无意义的扩展名筛选，因为文件集合当前只有 Markdown。
149. 跨文档正则搜索放入 P1，使用显式“正则”开关和 RE2/Rust Regex 一类保证线性时间的安全语义；支持常用字符类、捕获分组、选择、边界与重复，但明确不支持反向引用、前后查找或其他需要任意回溯的构造。表达式语法错误和不受支持特性在输入处说明原因，不自动降级为普通文本搜索。执行复用 N-03 的范围筛选，在隔离工作单元中运行，支持即时取消、结果数量/扫描资源上限和虚拟化流式输出；打开文档仍以未保存内存内容为准。若能从表达式提取固定字面量，则先利用全文索引缩小候选文件，否则受控扫描筛选后的文件集合。具体线性正则后端与 Unicode/CJK 行为由同一性能 PoC 验证，MVP 不提供跨文档正则搜索。
150. App 不提供交互式跨文档/全窗口批量替换：全文与正则搜索只负责定位结果，不能从搜索结果一次写入多个 Markdown 文件，也不建设批量 diff、事务日志、跨文件撤销或失败回滚系统。当前文档内已经确认的查找替换能力保持不变，并继续使用该文档自己的撤销历史。该限制针对搜索 UI 的批量替换能力，不改变用户逐篇编辑文件的能力，也不预先定义未来 Agentic 多文件变更的独立授权与审阅机制。
151. App 不提供独立的标题/大纲搜索入口或跨文档 heading 搜索索引。当前文档内的标题导航由大纲、动态 TOC 和已确认的当前文档查找覆盖，跨文档定位由 Quick Open 与全文搜索覆盖，避免增加一套高度重叠的搜索心智和快捷键。若后续文档大纲过长，只在该文档自己的大纲界面中增加即时过滤框；过滤数据来自当前实时 heading 列表、包含未保存内容，仅收窄当前大纲条目，不成为全窗口搜索能力或新的持久索引。
152. MVP 记录当前窗口范围内的最近文档，并将其作为 Quick Open 空查询时的首要结果。只有持久文档被成功打开或被用户实际激活时才更新 MRU 顺序；临时预览、后台恢复和索引访问不计入，关闭标签也不删除记录。MRU 使用规范化绝对路径标识、与磁盘 `mtime` 明确分离，采用有界持久列表并跨重启恢复；同一文件始终只有一条记录。展示时只返回仍存在且仍属于当前窗口统一文件集合的文档，移出集合或缺失的条目隐藏并可惰性清理。最近性只作为 Quick Open 空状态与同分排序信号，不改变用户输入查询后的主要匹配质量。
153. App 不提供收藏、书签或固定项目能力：不在文件树、标签、大纲、Quick Open 或独立面板中增加星标/书签入口，也不在 App 元数据或 Markdown 中保存收藏状态。长期定位依赖文件树的磁盘组织、Quick Open、最近文档以及文档内链接/大纲/TOC。该决定避免引入第二套人工组织维度、失效目标迁移与跨设备不可见的私有元数据。
154. P1 提供命名的保存搜索，但只保存查询定义，不保存或后台物化结果。每条记录保存在当前窗口的 App 元数据中，包含用户名称、搜索文本、范围/路径筛选 token、大小写选项和普通/正则模式；不修改 Markdown，也不创建文件树节点或智能文件夹。入口位于全文搜索的历史/已保存查询菜单，只有用户选择时才重新对当前索引与未保存内容执行，不在后台持续刷新。用户可重命名、编辑和删除；目录根被移除、正则能力不可用或 token 失效时保留原定义并显式标出问题，绝不静默扩大范围或改写查询。
155. 标签能力放入 P1，唯一内容真源是 YAML Frontmatter 的 `tags` 字段；支持 YAML block sequence 与 flow sequence，按文档级标签解析。App 不识别正文中的 `#tag`，不在 App 私有元数据中保存影子标签，也不根据文件夹、链接或模型自动生成标签。标签索引随 Frontmatter 解析结果增量更新，为标签展示、输入补全和 N-03 的 `tag:` 搜索筛选提供数据；未保存 Frontmatter 修改以当前内存内容为准。通过 UI 增删标签时只修改 `tags` 字段，必须使用能够保留其他字段顺序、注释、引号风格与未知 YAML 结构的 CST 级编辑；Frontmatter 无效时显示错误并禁止 UI 自动修复或覆盖，用户仍可在源码中处理。标签大小写归一与斜杠嵌套语义留给 N-11 决定。
156. P1 的 Frontmatter 标签使用 ASCII `/` 表达真正的父子层级：`project/alpha/mobile` 派生出 `project`、`project/alpha` 与完整叶标签的层级关系，但 App 绝不把派生父标签写回 Frontmatter。标签界面按树展示并逐级补全；`tag:project` 匹配该标签及所有后代，`tag:=project` 只做精确匹配。索引身份对每个路径段执行外层空白裁剪、Unicode NFC 与不区分大小写的 case-fold，源码原始拼写始终保留且 UI 编辑不自动统一大小写；前导/尾随 `/`、连续 `//` 或裁剪后为空的段落视为无效层级标签，保留原文并提示。P1 不提供父标签或子树的跨文件批量重命名。
157. App 不提供 Notebook、Collection、Library 分类或其他独立于磁盘的集合成员系统。用户加入窗口的顶层目录根及其真实子目录是唯一层级组织，移动文件或目录才改变其层级归属；P1 标签提供跨目录分类，保存的搜索提供按需动态筛选。App 不在私有数据库或 Frontmatter 中增加集合 ID/成员字段，不在文件树中混入虚拟集合节点，也不允许同一文件通过集合身份重复出现，从而保持本地 Markdown 与磁盘结构为唯一内容和组织真源。
158. Backlinks 放入 P1，并复用一个以规范化绝对路径为文档身份的增量链接索引。索引来源仅是当前窗口统一文件集合中的 Markdown 文档，识别标准本地 Markdown 链接以及 P1 的 Wikilink、标题锚点和块引用；打开文档的未保存内容覆盖其磁盘出链。每篇文档在正文之后拥有默认折叠的 App 附属反向链接区，折叠时只显示计数，展开后才虚拟化渲染，并按来源文档分组展示链接上下文与目标标题/块信息；该区域在所有文档模式下都不属于 Markdown 正文，不参与复制、正文搜索、字数或导出。点击来源沿用本地 Markdown 链接规则，在主区以预览形态打开并跳到发出链接的位置；若已打开则只激活原位置并保持模式。未解析或歧义链接保留在链接诊断数据中但不归给任意目标；仅出现文件名而没有实际链接的文本不算 Backlink。
159. P1 在文档底部增加与 Backlinks 并列、可独立折叠的“出链”附属区，完全复用当前文档的实时解析结果与 N-13 链接索引，不建立第二份索引。折叠时显示总数及失效/歧义计数，展开后按“内部已解析、内部未解析或歧义、外部链接”分组并虚拟化渲染；相同规范化目标合并为一项并显示出现次数，可展开查看各处上下文。点击内部目标沿用主区预览打开规则，点击某次出现可跳回当前文档对应链接，外部目标仍服从系统浏览器与联网隐私策略。该区域在所有模式下均不属于 Markdown 正文，不参与复制、正文搜索、字数或导出；链接状态随未保存内容即时更新，但折叠时不创建明细视图。
160. 当前路线不提供全窗口图谱、当前文档局部图谱或任何基于节点—边的知识可视化。N-13 的链接索引只服务于确定性的 Backlinks、出链和后续链接健康能力，不维护图布局、坐标、聚类、中心性、缩放视口或独立 Canvas/WebGL 可视化 bundle。该决定避免为低密度或大型链接集合引入持续布局计算、额外内存和高视觉噪声；用户通过精确列表和上下文完成导航。
161. P1 仅提供孤立文档识别，不提供“未链接提及”扫描。新增 `links:none` 搜索筛选，按需从 N-13 链接索引返回当前窗口统一文件集合中既没有来自其他集合内文档的已解析内部入链、也没有指向其他集合内文档的已解析内部出链的 Markdown 文件；自链接、外部网页链接、指向窗口外文件的链接、未解析链接和歧义链接均不使文档脱离孤立状态。筛选结果使用现有搜索虚拟列表和路径筛选，不建立独立面板或后台扫描。正文中仅出现文件名、stem 或 Frontmatter 标题而未形成明确链接的文本不索引为关系、不展示候选，也不自动改写链接。
162. Daily Notes 已识别为独立功能点，但留待后续专项设计；当前不决定是否提供、交付阶段、入口或具体行为，也不纳入 MVP、P1 或已承诺 Future。专项设计至少需要分别确定多目录根下的目标目录选择与缺失目录处理、日期/时区和文件名格式、模板来源与变量边界、已有文件打开与新建行为、冲突/非法路径处理，以及创建后如何进入当前窗口文件树和区域打开规则。在专项设计确认前不得按默认方案实现。
163. 跨文档任务汇总已识别为独立功能点，但留待后续专项设计；当前不决定是否提供、交付阶段、入口、查询形态或写回能力，也不纳入 MVP、P1 或已承诺 Future。专项设计至少需要确定任务语法与状态模型、索引范围、分组和筛选方式、定位原文的打开行为、是否允许从汇总结果修改原文、外部变更与未保存内容冲突处理、撤销边界，以及是否扩展截止日期、优先级、重复、提醒、依赖或批量操作。在专项设计确认前不得把 GFM 复选框索引自动演变为任务管理系统。
164. Metadata 查询 / Dataview 能力放入 Future，MVP 与 P1 只维持可复用的结构化元数据索引边界。Frontmatter、标签和链接的现有增量索引必须保持明确的数据来源、规范化身份、内容版本与未保存内容覆盖语义，使未来查询层可以只读消费，但当前不实现查询语言、表达式求值器、动态生成视图、正文内查询块、物化结果或后台持续重算。Future 专项设计再决定查询语法、类型系统、排序/聚合、缓存与失效、资源上限和结果呈现；任意 JavaScript、插件代码或其他用户脚本执行不因本决定获得授权。现有全文搜索、筛选 token 与保存搜索仍是独立能力，不伪装或演变为 Dataview 查询语言。
165. Database / Table View 放入 Future，并以 N-19 的结构化元数据模型与查询边界为前置依赖；MVP 与 P1 不实现文档数据库表格、属性列编辑、视图配置或专用数据库文件。未来若提供，Markdown 文件及其 Frontmatter 仍是内容真源，表格只是一组文档的投影视图，不在私有数据库中复制一份权威属性值。Future 专项设计再决定集合来源、列类型与缺失值、排序/筛选/分组、视图配置保存位置、只读或写回、批量编辑、内容版本校验、冲突与撤销边界；在这些问题确认前，不预设表格可编辑，也不让普通文件树或搜索结果逐步演变成隐式数据库。
166. App 不提供 Canvas / Whiteboard：不创建二维无限画布、自由卡片、连线、分组、缩放平移、空间布局或相应的独立持久化文件格式，也不为未来画布预留渲染引擎、文档卡片协议或私有布局数据库。Markdown 内已经确认的 Mermaid 等声明式图表仍按各自扩展渲染，它们不属于可交互白板；主副区域的文档布局也不演变为空间画布。该决定保持产品、启动体积、内存与交互工程聚焦于多 Markdown 文档的查看和编辑。
167. Web Clipper 放入 Future，并作为与桌面核心隔离的浏览器扩展及受控 App 导入接口专项设计。MVP 与 P1 不包含浏览器扩展、App 内 URL 抓取、网页正文提取、登录态共享、远程图片下载或网页持续同步，也不把 DOM 解析器和抓取依赖打进桌面核心启动路径。Future 需要单独确定浏览器与 App 的鉴权和最小权限、传输协议、用户预览确认、目标目录、文件命名、来源元数据、HTML 到 Markdown 转换、安全清洗、图片资产落盘、重复导入和失败回滚；所有网络访问与文件写入必须由用户明确发起并可审阅，不能因本决定默认开放本地监听端口或执行网页脚本。
168. OCR / 图片文字检索放入 Future，限定为完全本地、由用户明确启用并在隔离 worker 中执行；默认不扫描任何图片，也不调用云端 OCR 或上传图片。MVP 与 P1 的全文索引只包含 Markdown 可见文本及已确认的结构化数据，不抽取图片像素文字。Future 专项设计再确定按图片、文档、目录或窗口的触发范围，系统 API 与本地引擎选择，语言与准确率，CPU/内存/功耗预算，队列取消和低优先级调度，以及以文件内容哈希失效的有界缓存。识别文本属于可重建的 App 派生数据，不自动写回 Markdown、alt text 或图片文件；若接入搜索，结果必须明确标识来自 OCR，并定位到对应图片。
169. App 不提供内置文件状态或 Workflow：不定义 `draft`、`active`、`on-hold`、`completed`、`archived` 等保留状态，不提供状态徽标、专用切换入口、允许流转规则、状态驱动归档或自动化，也不占用 Frontmatter 的 `status` 字段。用户可以在 Markdown Frontmatter 中自行使用任意字段和值，并通过 P1 的属性筛选与保存搜索组织文档；这些值对 App 只是普通用户数据，不具有特殊生命周期语义。该决定不影响未来通用 Frontmatter 查看/编辑能力，但它不能暗中引入一套 App 工作流模型。
170. MVP 提供当前文档手动保存命令 `⌘S`，编辑模式与源码模式共享同一保存状态机。普通本地文件采用同目录临时文件写入、数据落盘并安全替换的流程，尽力保留原文件权限等必要元数据；任一步失败都不破坏原文件、不丢弃内存内容，临时产物可安全清理，文档保持 dirty 并展示可重试的 failed 状态。写入前必须比较磁盘版本与该文档的 last-saved 基线，发现外部变化就停止写入并进入后续 X-04/X-05 定义的冲突流程，绝不静默覆盖。每篇文档的保存请求串行化并绑定内容版本快照：只有对应快照成功替换后才能更新 last-saved 基线；若保存期间继续编辑，完成后当前文档仍为 dirty。UI 明确区分 dirty、saving、saved、failed，reading 模式下无改动时保存为空操作。特殊文件身份、权限和文件系统语义需要在保存层 PoC 中验证，但不得退化为不受保护的直接覆盖。
171. MVP 提供自动保存，但全局设置默认关闭。用户启用后，有确定磁盘路径的 dirty 文档在最后一次内容变更且输入法组合输入结束约 1.5 秒后，调用与 `⌘S` 完全相同的保存状态机、版本快照、安全替换和外部冲突检测；MVP 不另设可调延迟，也不维护第二条写入路径。每次继续编辑都会重置等待计时，未确定路径的新文档只进入崩溃恢复而不自动创建文件。单篇文档一旦进入 conflict，自动保存立即暂停直至冲突解决；普通写入失败后不得无间隔循环重试，只能在新的内容变更、用户手动重试或状态恢复后再次调度。设置开关只影响未来自动触发，不取消已开始的安全保存，也不改变 `⌘S`、关闭窗口提示或崩溃恢复行为。
172. App 不提供独立的失焦保存能力或设置。文档编辑器、主副区域、窗口或整个 App 失去焦点时，不因此立即写盘；切换标签、点击文件树、打开菜单和切换到其他 App 都只改变焦点，不改变保存策略。若用户已启用 X-02 自动保存，原有约 1.5 秒 idle 计时可在失焦后正常到期，但失焦既不加速、重置也不取消它；若自动保存关闭，则只能由 `⌘S`、明确的关闭/退出确认或恢复机制处理 dirty 内容。关闭标签、窗口或 App 是生命周期事件而不是失焦事件，其未保存内容处理需要独立规则，不能借失焦保存绕过用户确认。
173. MVP 监听已打开文档的外部磁盘变化，并区分 clean 与 dirty。文件 watcher 事件必须合并去抖，在后台重新读取并用内容版本/哈希确认真实变化；由 App 自己的 X-01/X-02 保存产生且与已确认保存版本相同的事件应被识别为自写回响，不重复刷新。clean 文档检测到真实外部内容变化时自动更新 last-saved 基线和当前内容，保留该文档原有模式，并使用已确认的稳定内容块锚点、视口偏移与可映射的光标/选区尽量恢复位置；失败时回退到最近有效位置并给出轻量提示。dirty 文档检测到外部变化时绝不替换当前内存内容，立即进入 conflict、保存命令改为冲突处理入口且自动保存暂停，同时保留 last-saved、local 与最新 external 三个版本供 X-05 使用。后续连续外部变化只更新 external 候选并提示版本已再次变化，不在后台自动合并；监听与读取不得阻塞编辑主线程。
174. MVP 提供基于源码文本的三方冲突比较与显式解决流程，输入固定为 last-saved 基线、当前 local 内存内容和最新 external 磁盘内容；不以渲染后的 Markdown 做语义 Diff，不自动合并，也不向正文插入 Git 风格冲突标记。冲突界面显示可对应的 base→local 与 base→external 差异，并提供一个以 local 为初始值的可编辑结果；比较计算在可取消的后台任务中进行，大文档采用增量/虚拟化展示和资源上限，并复用 CodeMirror 6 编辑栈而不引入第二套编辑内核。用户可以手动编辑结果后保存、接受 external、保留 local 并覆盖，或将 local/合并结果另存为新文件。任何写回原路径的操作都必须先重新读取并确认磁盘仍是界面显示的 external 版本；若又发生变化，则刷新 external 并保持 conflict，绝不覆盖新版本。接受 external 会明确确认丢弃 local 修改并更新内容/基线；另存为不改变原路径的 external 文件；只有原路径被安全解决后才退出 conflict 并恢复自动保存。
175. MVP 在权限受限的 App 数据目录中为 dirty 文档维护崩溃恢复记录，采用短间隔合并写入的增量变更日志与定期完整内容检查点；写入、压缩和校验在编辑主线程之外执行，具体合并间隔、检查点阈值与全局磁盘配额由恢复 PoC 按可接受数据损失窗口和大文档写入成本确定。记录包含文档规范化路径或未命名文档 ID、last-saved 基线身份/哈希、内容版本和必要时间戳，使用校验和与格式版本隔离损坏条目；它是仅用于灾难恢复的本地派生副本，不同步、不充当版本历史。异常退出后的下次启动展示恢复记录及其与当前磁盘版本的关系，用户可以预览/比较、恢复成 dirty 文档、另存或明确丢弃；App 绝不直接用恢复内容覆盖原 Markdown。只有对应内容成功保存、用户明确丢弃，或确认某条记录已不再需要时才清理；单条损坏或路径失效不能阻塞其他记录恢复。正常关闭标签、窗口或 App 仍须走未保存内容确认，不能因为存在恢复日志就静默丢弃内存状态。
176. P1 提供可选的应用内版本历史，全局默认关闭。启用后只在 X-01/X-02 经 App 成功保存且内容版本确实变化时，在权限受限的 App 数据目录记录该文档版本；使用周期完整检查点、压缩增量链和后台压缩/整理，不在每次按键时创建长期版本，也不把历史文件写进用户 Markdown 目录。实现必须同时执行单文档与全局磁盘配额、可解释的保留/压缩策略、损坏链隔离和显式清理入口，具体默认配额与保留梯度由 P1 存储 PoC 决定。历史界面按时间只读预览，并复用源码 Diff；选择恢复时只把该版本载入为当前 dirty 内存内容，保留原路径并通过 X-01 的外部版本校验和安全保存后才可能落盘，不直接覆盖文件、不删除恢复点。该历史与 X-06 崩溃恢复、Git/Time Machine 相互独立，不宣称捕获其他程序的每次写入，也不作为跨设备同步或备份系统。
177. Git 历史查看放入 Future；MVP 与 P1 不探测 Markdown 是否位于 Git 仓库，不遍历 `.git`、不调用系统 Git 或打包 libgit、不维护仓库状态 watcher，也不在启动或文件打开路径增加 Git 工作。用户在 P1 及以前使用外部 Git 工具查看历史，外部 checkout/restore 对已打开文件产生的变化仍只按 X-04/X-05 的普通磁盘修改规则处理。Future 若实现，范围首先限定为用户按需触发的本地只读文件历史、历史内容和源码 Diff，不自动 fetch、不访问网络、不改变 index/working tree；历史版本恢复仍只载入为 dirty 内容并经 X-01 保存。后端、仓库信任、子模块/worktree、重命名追踪、资源超时与错误隔离留待专项设计，且不得与 X-07 App 版本历史合并成同一数据真源。
178. App 不提供任何会改变 Git 仓库状态的能力。即使 Future 实现 X-08，只读边界也保持不变：不执行 `git add`、commit、amend、checkout/switch、branch、merge/rebase、stash、tag、reset、push/pull/fetch 或凭据管理，不修改 index、refs、配置和远端状态，也不提供“自动提交”设置。用户使用外部 Git 工具完成这些操作，产生的工作区文件变化由 X-04/X-05 按普通外部修改处理。未来 Agentic 多文件编辑也不因其身份获得 Git 操作权限，不得把提交当作保存、历史或任务完成的隐式步骤；若以后要重新考虑，必须作为新的高风险外部状态能力单独设计和授权，而不是扩张本条或 X-08。
179. App 不提供“导出原始 Markdown”“导出副本”或“Markdown + 资产便携包”命令。磁盘上的本地 `.md` 文件本身就是可由 Finder、脚本、Git 或同步工具直接复制和迁移的内容真源，App 不再制造语义相同的第二份导出副本，也不扫描引用资产、复制资产目录、打包 ZIP 或为迁移改写链接。dirty 内容需要通过 X-01 保存、另存为或 X-06 恢复流程明确落盘，不能借“导出”绕过当前文档的保存/冲突状态。该决定只取消原始 Markdown 形态的专用导出，不预先否定 HTML、PDF 等转换型导出能力。
180. P1 提供当前文档的安全单文件 HTML 导出。导出从用户确认时的当前内存内容快照生成，不要求先保存，也不改变原文档路径、dirty 状态或 last-saved 基线；复用阅读模式的规范解析/渲染结果和当前窗口阅读主题的可导出样式快照，不维护另一套 Markdown 方言。输出内联必要 CSS 与受支持的本地图片数据，Math、Mermaid 等只输出静态且已清洗的结果；不包含 JavaScript、事件处理器、可执行 HTML、远程 CSS/字体或其他主动内容。远程图片默认不下载且不保留会在打开文件时自动联网的资源加载，降级为带来源链接的占位；普通外部超链接仍可由用户点击。Raw HTML 继续服从已确认安全白名单，SVG 保持 inert。导出在后台执行并可取消，写入目标文件时采用安全替换；本地资产缺失、不支持或总体积超过经 PoC 确定的单文件阈值时必须列出问题并让用户取消或按明确降级结果继续，不能静默丢失内容。
181. PDF 导出放入 Future，与已经确定的“不在 App 内预览 PDF”保持独立。MVP 与 P1 不提供 PDF 导出入口，不绑定 macOS 打印/PDF API，不打包 Pandoc、Chromium 或另一套排版引擎，也不为 PDF 在启动路径加载分页依赖；用户可将 X-11 单文件 HTML 交给浏览器或系统打印工具自行生成 PDF。Future 专项设计必须基于同一规范 Markdown 语义评估原生打印管线与可选转换后端，明确纸张、方向、页边距、页眉页脚、分页控制、目录/书签、脚注、代码块、表格、Math/Mermaid 静态输出、字体嵌入和链接行为，并通过长文档及跨语言字体的分页稳定性测试后再选择实现。导出仍应使用当前内存快照、后台可取消且不改变保存状态，但这些细节在专项方案批准前不形成实现承诺。
182. DOCX 导出放入 Future，且只考虑用户自行安装并明确配置的 Pandoc 一类外部转换器；App 不随包分发转换运行时、不自动下载或安装依赖，也不在启动和普通文档路径探测可执行文件。Future 入口只有在用户发起导出时才校验工具路径与版本，以参数数组而非 shell 字符串启动受限子进程，使用当前内存快照的临时输入，支持取消、超时和临时文件清理，并把 stdout/stderr 转换为可理解的结果。专项设计需要确定 Markdown 扩展到 DOCX 的映射、图片/Math/表格/脚注/Raw HTML 降级、参考 DOCX 模板、资源访问范围与不受支持方言报告；导出是有损转换，必须在完成后列出警告，不能宣称与编辑/阅读渲染像素一致，也不能改变源文档保存状态。
183. App 不提供 ePub 导出。MVP、P1 与 Future 路线均不建设电子书元数据/封面编辑、章节拆分、目录生成、CSS 模板、字体与图片资产打包、EPUB 规范校验或阅读器兼容测试，也不因为 X-13 未来可能支持外部 Pandoc 就自动暴露 ePub 目标。需要电子书发布的用户直接使用 Pandoc、Calibre 或其他专业出版工具处理本地 Markdown；App 的 X-11 HTML 导出可作为外部流程的可选输入，但 App 不跟踪、校验或支持该外部产物。
184. App 不提供 LaTeX 导出。MVP、P1 与 Future 路线均不建设 Markdown 到 `.tex` 的转换规则、文档类与宏包选择、模板系统、交叉引用/文献映射、图片路径管理、Math 环境转换或 TeX 编译链，也不从 X-13 的 Future 外部 DOCX 转换器自动扩张出 LaTeX 目标。需要学术排版的用户直接使用 Pandoc、Quarto 或 TeX 生态工具处理本地 Markdown；App 不生成、编译、预览或校验其 LaTeX 产物。本决定不影响 Markdown 正文中已确认的 Math 语法和静态渲染，它们不等同于通用 LaTeX 文档支持。
185. App 不提供幻灯片模式或演示文稿导出。Markdown 的 `---` 继续只按已确认语法解释为 Frontmatter 分隔或 thematic break，不获得隐式分页语义；App 不建设幻灯片切分规则、版式/主题、演讲者备注、动画/转场、演示视图、遥控、Reveal.js 运行时、PPTX/PDF 输出或相关资产管线，也不从 X-13 的外部转换器扩张出演示目标。需要演示的用户直接使用 Marp、Slidev、Reveal.js、Pandoc 等专用工具处理本地 Markdown，App 不跟踪或支持其产物。
186. MVP 的普通复制按文档模式写入系统剪贴板的多 MIME 表示。编辑模式中，`text/plain` 为当前选区对应的原始 Markdown 源片段，`text/html` 为同一选区经规范渲染器生成并清洗的语义 HTML；阅读模式中，`text/plain` 为用户看到的可见文本，`text/html` 为所选渲染结构的安全 HTML；源码模式只写入原始 `text/plain`，不生成富文本。HTML 必须移除脚本、事件属性、远程样式/字体、App 私有 UI 和不安全 Raw HTML，Math/Mermaid 等只使用静态结果，不携带自动联网或可执行内容；剪贴板中不夹带文档绝对路径、索引 ID 或其他 App 元数据。序列化直接复用现有解析/渲染数据并设置选区大小/耗时上限，超过上限或部分选区无法可靠渲染时仍保证纯文本复制成功，同时提示富文本表示已降级；复制不得阻塞输入或修改文档。目标应用自行选择支持的 MIME，App 不针对 Word、飞书等维护专用格式分支。
187. App 不提供 `.html`、`.htm`、RTF 或其他富文本文件的单篇/批量导入命令，不建设文件级转换预览、DOM 清理报告、远程资源抓取、本地图片搬运或新 Markdown/目录批量创建流程。MVP 已确认的 E-24 智能粘贴是唯一的富文本转 Markdown 入口：用户在浏览器或原应用中选择并复制所需内容，由编辑模式对剪贴板 HTML 清洗后作为一个可撤销 transaction 插入当前文档；源码模式仍只粘贴纯文本。该入口面向用户明确选择的片段，不承诺完整保留网页布局、文档样式、脚本、隐藏内容或整站结构，也不演变为 Web Clipper 或迁移工具。
188. App 不提供 DOCX、ePub 或其他办公/出版容器到 Markdown 的导入。MVP、P1 与 Future 路线均不打包或调用此类输入转换器，不解析 OOXML/EPUB 包，不执行章节拆分、样式/批注/脚注映射、图片/附件提取、资产目录创建或有损转换报告。用户使用 Pandoc、Calibre 或原应用先导出为本地 Markdown，再通过既有“打开文件/打开文件夹”加入窗口；App 只对转换后的 Markdown 和用户明确加入的资产负责，不保留对原容器的关联、同步或往返编辑。本决定不影响 X-13 Future 的单向 DOCX 导出候选，两者不得相互推导出双向格式支持。
189. App 不提供 Obsidian、Joplin、Bear、Notion 或其他笔记产品的来源专用迁移器，不读取其数据库/私有导出包，不映射 Notebook、标签、内部链接、ID、附件、时间戳或专有语法，也不建设逐来源兼容矩阵、迁移预览、原始备份和失败回滚。已经是本地 Markdown 目录的来源（例如普通 Obsidian vault）由用户直接通过“打开文件夹”加入窗口，App 不复制或接管该目录；专有来源必须先用原应用或外部工具导出为本地 Markdown/资产目录，再按普通文件处理。遇到未支持的 Markdown 方言继续遵循现有“保留原文、可降级显示、不静默改写”原则，但 App 不承诺还原原产品语义。
190. App 不提供“导出主题包”“导出模板”或内置主题/模板创作打包工具。ThemePackage 的源目录 `theme.json + theme.css + assets/` 本身就是版本化、可复制和可分发的载体；主题作者应保留并通过 Finder、压缩工具或版本控制分发该源包，App 的已安装副本不被视为可编辑的权威源码，也不负责反向生成 ZIP。当前没有已确认的通用模板系统，X-21 不得以“导出模板”为由提前创建模板格式；Daily Notes 等待专项设计的功能也不受其隐式约束。P1 的外部主题安装只负责校验与安装 ThemePackage，不自动扩张为创作或发布工具。
191. MVP 提供 App 全局外观选项 `System / Light / Dark`，默认 `System` 并跨重启保存；`System` 在 App 运行期间实时响应 macOS 外观变化。该选项控制窗口外壳、文件树、标签、工具栏、浮层、编辑模式和源码模式，统一通过语义 design tokens/CSS variables 与共享代码高亮 token 切换；必须在首帧绘制前应用已解析的有效外观，运行时切换只更新样式，不重新解析 Markdown、不重建编辑器、不改变文档模式、选区或视口。该设置是 App 级而非窗口级，应用于所有窗口；窗口级阅读 ThemePackage 继续独立控制阅读正文，U-01 不强制替换或重新选择阅读主题。系统通知异常时保持最近有效值，不能闪回默认浅色。
192. App 不提供内置阅读主题市场、在线注册表或主题自动更新。P1 的 U-03 只允许用户通过系统文件选择器明确选择本地 ThemePackage，由 App 离线校验清单、CSS、资产边界和兼容版本后安装；App 不提供主题发现、搜索、推荐、下载、评分、评论、付费、账号、更新检查、远程下架或遥测，也不在后台访问主题服务。用户在 App 外获取新版本并再次本地安装，主题包的来源、真实性与分发渠道由用户自行决定；App 的安全校验不能被视为内容背书。内置主题仍随 App 版本更新，但界面上与其他 ThemePackage 不分类的既有决定不变。
193. MVP 提供两个 App 级文档字体设置：编辑模式正文使用的 prose font family，以及源码模式、行内代码和代码块使用的 monospace font family；所有窗口共享并跨重启保存。App 外壳、文件树、标签、工具栏和其他 UI 始终使用 macOS 系统 UI 字体，不允许用户覆盖；阅读模式的正文与代码字体完全由当前窗口 ThemePackage 控制，U-05 不向其注入全局字体覆盖。字体列表只包含系统可用的本地字体，并仅在打开字体设置时惰性枚举，不下载、不加载远程字体，也不把字体文件复制进 App。设置保存稳定字体标识并带明确 fallback stack；字体被卸载或加载失败时使用 fallback 并提示，不改变用户原选择。运行时切换只更新 CSS/font tokens 和编辑器测量，使用稳定内容锚点恢复视口，不重新解析 Markdown、不写入文档。
194. MVP 提供 App 级基础排版设置：编辑模式可调 prose font size、unitless line-height 与 paragraph spacing，源码模式可独立调 monospace font size 与 unitless line-height；所有值在可访问性与布局安全范围内连续调整、即时预览、跨窗口和重启保存，默认值及上下限由排版/长文档 PoC 确定。阅读模式的基础字号、行高和段距完全由窗口 ThemePackage 控制，U-06 不覆盖主题。R-17 主区域正文缩放作为各模式基础字号之上的统一倍率：编辑/源码的 unitless 行高和 em 型间距随字号自然缩放，阅读按主题基础排版缩放；副区域始终使用 100% 基础值。修改设置或缩放只更新 CSS variables/编辑器测量并按稳定内容锚点恢复视口，不重新解析、修改 Markdown 或写入主题包；源码模式没有段落语义，因此不提供段距设置。
195. App 不提供内容宽度设置，不保存按 App、窗口或文档的窄/中/宽或自定义 max-width。编辑模式使用 App 固定的响应式排版规则：宽区域内正文居中并受内置可读性上限约束，区域变窄时自动占满可用宽度并保留安全内边距；源码模式始终使用区域可用宽度与固定安全内边距。阅读模式的正文宽度、最大宽度和内边距完全由当前 ThemePackage 控制，但仍必须被文档区域边界裁定，不得撑破主副区域的结构最小尺寸或制造页面级横向溢出；超宽表格/代码等内容按各自横向滚动规则处理。副区不另设宽度策略，统一由同一响应式容器自然收窄。U-06 和 R-17 只改变排版尺寸/倍率，换行随之重排，但不改变任何内容宽度配置，因为不存在该配置。
196. 界面密度设置放入 P1，MVP 只提供一套固定的默认密度，不显示 compact、comfortable 或自定义行高/间距入口。默认密度统一定义文件树、主区标签、菜单、工具栏、搜索/命令结果列表等 App UI 的设计 token，并保证点击目标、焦点环和文字截断满足可用性；它不改变编辑、阅读、源码正文排版，也不改变已确认的副区标题栏、分隔线命中区和主副区域最小尺寸规则。P1 若实现，范围优先限定为 App 级“紧凑 / 舒适”固定档位：通过离散 token 集整体切换，不允许连续调节或按窗口/组件分别覆盖；所有虚拟列表必须为每一档使用可预测的固定行高并在切换后重测可见范围、保持稳定选中项与滚动锚点，避免动态高度破坏虚拟化性能。具体受影响组件、档位尺寸和可访问性下限由 P1 的界面 PoC 决定。
197. MVP 将文件树侧栏的显示/隐藏状态和展开宽度作为窗口会话布局的一部分保存并跨重启恢复，不采用 App 全局共享值，也不为此引入名为 Workspace 的独立产品对象。每个窗口会话同时关联其已加入的顶层目录/单文件集合与布局状态；用户通过菜单、快捷键或侧栏切换控件显式显示/隐藏文件树，并可拖动侧栏与内容区之间的分隔线调整宽度。隐藏只移除侧栏的布局占位，不卸载文件集合、关闭 watcher、清除选择或改变文档打开状态；再次显示时恢复该窗口上次有效展开宽度。新建窗口使用产品默认的显示状态与宽度；恢复时若旧宽度不再适合当前窗口尺寸，则在侧栏最小可用宽度和为主内容区保留的最小空间之间夹取，不造成横向溢出。拖动和切换只更新布局 token 并合并持久化，不触发目录重扫、Markdown 重新解析或文件树数据重建。
198. MVP 不提供窗口底部常驻状态栏，也不建设状态栏模块开关、排序或插件插槽。保存中、已保存、dirty、外部变更与冲突等状态由文档标签附近的状态标识和必要的就近提示承担；文档模式继续由主区悬浮工具栏或副区标题栏呈现，操作结果使用短暂提示或专用流程，不为这些信息永久占用纵向空间。源码模式的光标行列、编码和换行符不在 MVP 常驻展示，需要时可在对应命令、打开/保存诊断或后续专项能力中提供；R-16 已延后的字数、字符数和阅读时间也不预设必须进入状态栏。Future 若重新评估状态栏，必须先证明存在多个值得持续展示的模块，再单独决定是否可配置；MVP 不为假设性模块预建框架。
199. 完整键盘可操作是 MVP 验收门禁，而不是上线后的补充优化。用户必须能在不使用鼠标的情况下完成 MVP 核心流程：加入目录或单文件、导航文件树、打开/预览/固定/关闭文档、切换和重排主区标签、在主副区之间移动文档、展开/收起区域、切换文档模式、查找与执行命令、编辑和保存，以及操作所有菜单、弹层、对话框与冲突/恢复流程。纯拖放交互必须提供统一命令注册表中的等价命令；可拖动的侧栏、主副区和副区文档分隔线必须可聚焦并用键盘按离散步长调整，同时遵守既定最小尺寸和满载规则。文件树、标签组、菜单和结果列表采用符合其语义的方向键、Home/End、Enter/Space、Escape 与 roving tabindex 行为，焦点顺序稳定且焦点环始终可见；操作完成、失败和焦点迁移不得只靠视觉或 hover 表达。MVP 使用已确认的固定 macOS 快捷键映射，不提前实现 E-23 的 P1 自定义快捷键，但所有入口必须复用同一 command ID 与可用性判断，避免鼠标、菜单和快捷键形成不同逻辑。
200. Screen Reader 的正式支持放入 P1；MVP 的 U-11 完整键盘验收不等同于、也不宣称通过 VoiceOver 等屏幕阅读器。MVP 不建立屏幕阅读器专用公告层、虚拟列表可见范围播报、复杂编辑装饰朗读规则或完整辅助技术测试矩阵，但在不扩张范围的前提下仍优先使用原生语义元素、可访问名称和可预测焦点，避免为 P1 制造明显结构性阻碍。P1 将以 macOS VoiceOver 为首个明确目标，专项覆盖 App 外壳、文件树、主区标签、副区平铺文档、阅读语义结构、CodeMirror 编辑/源码界面、虚拟化列表、弹层/对话框以及保存、冲突和恢复反馈；验收需要真实 VoiceOver 手工流程与自动化语义检查结合，并单独定义长文档虚拟化下的导航和公告策略。在该专项完成前，产品不得对外声称完整 Screen Reader 支持。

## 当前待决策项

`U-13 高对比度`：是否为低视力或高对比需求提供专门支持，并把“不只依赖颜色表达状态”纳入哪个阶段？

### R-10 大纲呈现方式：暂缓项

已识别约束与候选：

- 不采用与文件树互斥的全局左栏：无法同时查看文件树，且副区多文档时归属与空间距离不清晰。
- 不优先新增全局右栏：会与副区争夺横向空间并增加窗口最小宽度。
- 候选 1：文档内左侧常驻大纲，展示时挤占该文档正文宽度；需要定义文档最低可用宽度及副区降级策略。
- 候选 2：每篇文档的“大纲”按钮打开锚定弹层；选择标题后关闭并跳转，不改变正文布局。
- 候选 3：文档顶部显示当前标题路径/面包屑，点击后展开完整层级；常驻占用小，但更偏导航而非持续总览。
- 候选 4：自适应双形态——宽文档允许把大纲固定在内部左侧，窄文档使用按钮弹层；能力完整但状态与缩放规则更复杂。

## 主副分栏候选规则

1. 窗口固定按左右方向分成主区域与副区域，分隔线可拖动调整比例。
2. 主区域拥有标签集合和当前激活文档。
3. 副区域没有标签集合，所有加入副区域的文档同时平铺显示。
4. 副区域文档固定从上到下纵向平铺。
5. 副区域文档之间的分隔线可拖动，以调整各文档展示比例。
6. 文件树文档可拖入主区或副区；主区标签可拖入副区；副区文档可拖回主区成为激活标签。
7. 同一个文档只能位于一个区域；跨区域操作是移动展示身份，不产生副本。
8. 文件树双击在最后激活的区域打开；如果没有激活区域，则在主区域打开。
9. 文件树单击临时预览始终在主区域进行，不占用副区域。

## 副区新增文档高度算法

设副区总可分配高度为 `H`，已有文档数量为 `n`，文档 `i` 当前高度为 `hᵢ`，最低高度为 `m`。每个文档高度口径包含它需要保留的标题栏与分隔线占位。

1. `n = 0` 时，新文档取得全部高度 `H`。
2. 对已有文档先计算候选高度 `cᵢ = hᵢ × n / (n + 1)`。
3. 若 `hᵢ = m`，最终旧高度保持 `m`，不采用候选高度。
4. 其他旧文档的最终高度为 `max(cᵢ, m)`；候选高度等于最低高度时也取 `m`。
5. 全部旧文档完成第一轮计算后，新文档暂定高度为 `h_new = H - Σhᵢ_final`。
6. 若 `h_new ≥ m`，加入成功，新文档追加到底部并取得 `h_new`。
7. 若 `h_new < m`，计算缺口 `d = m - h_new`，找出仍满足 `hᵢ_final > m` 的旧文档集合 `F`。
8. 由 `F` 中的旧文档平均承担缺口；任一文档最多只能缩小到 `m`。本轮触底的文档退出 `F`，未补足的缺口由剩余文档继续平均承担，直至补足或 `F` 为空。
9. 补足缺口后，新文档高度取 `m`，加入成功；旧文档采用让位后的高度。
10. 若所有旧文档均已达到 `m` 仍无法让出完整缺口，才判定副区满载：不加入文档，所有旧文档恢复操作前的高度与顺序。
