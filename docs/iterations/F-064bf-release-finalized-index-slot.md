## 范围

最后移除匹配的 v4 收尾清单，保留已空的私有槽。隔离夹具验证同一槽可由新的授权范围显式创建索引。

## 最小实现

1. 请求携带范围键、代数及 v2 摘要。在同一既有私有槽租约内，只接受固定 v4 清单和本次租约。原名、待回收名、旁车和其他成员须均缺失。已有新索引、异常链接、外来成员或目标不匹配时拒绝。
2. 持有私有槽和固定清单的描述符，核对原清单字节、身份、调用方和租约。原生入口只移除固定 `catalog.json`，复核该名称消失及持有文件的链接数归零。同步私有槽并复核只剩本次租约，然后释放租约。结果不明返回 `UNKNOWN`。
3. 同一请求遇到独立核对的空槽，只同步并返回 `alreadyEmpty`。该回执表示当次为空。之后出现的新索引不会被旧请求移除。
4. 当前原生写入入口冷启动前也须在同一租约下核对槽内只有本次租约，并在启动 Worker 前再次验证。正常空槽可继续创建索引。没有自动清理、遗留租约解除或真实用户缓存操作。

## 最小验收

- 正式原生隔离夹具完成前置步骤，移除 v4 后保留同一私有槽。新进程复核空槽，再用不同的授权范围显式建索引，验证旧请求无权修改新索引。
- 覆盖旁车仍在、异常链接、外来文件、目标不匹配、租约、取消和移除后同步失败。空槽确认与完成当前目标的回执分开。
- 包内定向复跑，实际 WK 回归普通搜索和定位。
