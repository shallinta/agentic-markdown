# F-039a 观察真实窗口中后台标签的资源

> 状态：alpha.273 普通 WK 和诊断对照经受托验收及独立复核通过。前置 F-069a 控制器基线和 F-012h 非活动解析状态回收。

## 功能说明

在已验的 macOS WK 包里观察主区多个标签打开、切换及关闭时的编辑视图和派生资源。先分清切换时卸载的视图、暂停的解析状态和始终保留的文档状态，再据实决定下一片是否需要为某类缓存补取证。本片不调整回收策略。

## 观察对象

| 对象 | 当前源码边界 | 本轮证据 |
| --- | --- | --- |
| 主区编辑视图 | `DocumentServicePanel` 只给活动编辑或源码文档挂载 `MemoryEditor`。文档变化时旧 `EditorView` 的清理解绑回调、记录位置并调用 `destroy()` | 普通窗口观察活动编辑区、切换后焦点和编辑区身份。AX 未显示旧编辑区仅说明当前可见结果，不单独证明旧对象销毁或垃圾回收 |
| 编辑派生解析 | 控制器切换活动文档时暂停旧语言状态，并在新活动槽恢复；长文解析会话另持 Worker 和自有派生引用 | F-012h/F-069a 提供控制器语言配置及树长基线。如需直接观察销毁回执，可另跑既有 WK 编辑探针，并与普通标签现象分开记录 |
| 当前规范解析 | 主窗 `createDocumentCanonical` 绑定活动文档的身份、缓冲版本与原文。失配使旧结果失效，Worker 由会话结算或取消时终止 | 在隔离窗口使用已有「实验：解析当前文档」，核对旧结果不跨标签显示，返回可重新解析。同一结果消失不表示 WebKit 已回收内存 |
| 权威文档状态 | 控制器持有已打开标签的原文、缓冲区版本、模式、选区、视口位置及撤销历史 | 在正常打开路径实际修改、离开并返回，核对状态及撤销结果。单独关闭后检查对应标签消失，固定标签也适用 |

## 执行步骤

1. 使用已验且源码对应的原生 WK 包，记录版本、归档摘要、系统、机器和探针开关。各档使用不同的私有 `AGENTIC_MARKDOWN_HOME`、`HOME`、`TMPDIR`，只打开自建目录。沿用 [F-069a](F-069a-multitab-performance-baseline.md) 的 4096 字节生成规则及编号，含 BOM、CRLF、中文和 emoji。保存验前 SHA。应用通过系统选择器授权目录，通过文件树或已有打开入口逐篇打开。记录实际成功打开数，拒绝或超时保留原结果。
2. 普通主窗先完成 1、5 两档。1 标签是打开、编辑及关闭的对照，不计切换。5 标签覆盖至少两次离开和返回、一个固定后台标签、另一个源码标签，以及关闭非活动标签和关闭最后一个标签。记录打开前、打开后、切换后、全部关闭后四个状态。若同一打开路径能可靠重复，再用独立实例完成 20、50 档，保持每档语料前缀与操作顺序一致。未执行档位单独列出，不能用 F-069a 的同档数据补齐。
3. 在多标签档为固定样本留下可识别的未保存编辑、选区和非首屏位置。打开其他标签，返回时核对活动文档、模式、标记与位置。用实际替换确认选区，用撤销回到原始内容并确认干净。必要时临时保存自建夹具核对字节并恢复，最终逐个重核 SHA。打开的文件仍留在文件树时，区分关闭标签与移除授权。末尾正常退出并确认对应实例结束。
4. 另用同包开既有 `AGENTIC_MARKDOWN_EDITOR_FAULT_LAB=1` 的主窗诊断。仅使用焦点诊断和当前解析按钮，不注入故障。在两个合成标签之间观察编辑焦点摘要、返回后的选区端点和旧规范解析结果失效。焦点诊断用匿名节点编号，不读后台节点，也不替代正常启动的操作。若需 Worker 与销毁的直接对照，另开同包 `AGENTIC_MARKDOWN_PERF_LAB=1 AGENTIC_MARKDOWN_PERF_EDITOR=1` 的编辑视图实验，或以 `AGENTIC_MARKDOWN_PERF_PARSER_WORK=1` 代替编辑探针开关，记录实验自己的完成、终止及销毁指标。实验宿主的合成视图回执单列，不能写成普通主窗每个后台标签的资源计数。
5. 能确认进程归属后，再在四个阶段记录对应进程的 RSS，注明进程类型、取样时机和归属依据。Bun 主进程与 WebKit 内容进程分开。无法归属或缺少 WebView 堆指标时记未观测，不合并系统里其他 WebKit 进程。自然退出、视图销毁和派生引用移除都不等于系统内存即时下降。桌面工具往返耗时不能作渲染耗时。

## 最小验收

- 至少完成普通 WK 的 1、5 标签档和诊断对照，留实际打开数、活动编辑区与切换证据、权威状态和撤销回执、正常退出及夹具摘要。20、50 档若执行，按同样口径另附结果。
- 把源码清理点、普通窗口观察、受控 WK 探针和进程采样分开。直接计数缺失时记证据缺口，不用 Bun 替代 WK，不从切换或关闭推断泄漏、GC 或资源字节。首轮失败及未执行项保留，独立复核证据。
- 本片不设时间或内存门槛，不更改 App 代码、版本或缓存策略。OBL-024 的分类配额、总上限和 LRU 仍开放，副区可见文档保护与 F-072 汇合后续承接。

## 继承约束检查

- F-002 仅本机合成文件和隔离窗口，最终离线留人工。
- 中文与外观无新增产品界面，实验诊断只使用已有入口。
- 命令与键盘沿用正常标签打开、切换、撤销及退出；区分自动化动作与实体输入。

## 实际观察（2026-11-07）

- 沿用已验 alpha.273 / `3t1sdjmhg44vu`，macOS arm64 / 27.0（26A428），MacBookPro18,3。普通 1 标签、普通 5 标签和 2 标签诊断各用私有数据、HOME 和临时目录。每篇 4096 字节，BOM、CRLF、中文和 emoji 沿用 F-069a 的样本字节，三个实例均自然退出 0，8 份夹具 SHA-256 验前后相同。
- 单标签实际编辑再撤销，状态回到已保存。关闭后编辑区不再出现在 AX，文件树仍保留该条目。五标签逐一打开成功。将 2 号切至源码，在 0 号编辑模式文末添加标记并选中，再固定 0 号，依次切到 3、2 和 0。2 号仍为源码，0 号返回时仍在文末，草稿、固定状态与实际选区都在。粘贴替换恰好覆盖标记，连续撤销先恢复标记，再回到干净正文。关闭非活动 4 号未切走 0 号，关闭其余标签和固定 0 号后五条文件树项目仍在，当前无活动编辑区。
- 诊断实例只用已有焦点诊断与当前规范解析。匿名焦点摘要记录两次 `editor → editor`、`same=false`，只反映当时选区端点归属。0 号结果完成后切到 1 号显示「尚无当前结果」，再切回 0 号仍为空，手动重算后重新显示 120 个顶层块。本次没有注入编辑故障或采样旧编辑器对象。
- 五标签隔离实例中，以启动器直接子进程确认 Bun 归属。欢迎页、五标签打开、切换及撤销后、全部关闭后的 Bun RSS 抽点分别为 172,320、189,776、200,192、200,688 KiB。WebKit 内容进程与 JS 堆未测，读数只描述这一实例的时点，不能用于推断内存泄漏或对象回收。本片未跑 20、50 档，也未运行受控销毁计数探针，未修改缓存策略。
