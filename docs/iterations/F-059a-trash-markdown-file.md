## 功能与范围

承接总账第320条/W-12与MVP F-059：用户显式选择当前窗口已授权的单个 Markdown 文件，确认后只通过系统废纸篓机制处理磁盘文件；不永久删除，不清空废纸篓，不把“从窗口移除”当删除。支持根内文件及独立文件入口，不以当前活动标签猜测树目标，不自动打开正文。目录及真实完整子树、未显示资产的整组影响清单属于后续F-059切片；主副区完整路由不在本片。

磁盘实操作前必须明确中文确认文件名与路径、说明进入系统废纸篓及受影响标签。若有打开/未保存文档，沿既有保护解决保存、放弃或取消：用户可先正常保存，回来重新确认；本片不自动保存、不另存为。选择放弃不提前销毁编辑缓冲/撤销历史；只有系统确认成功后才关闭标签并更新集合。取消及已知失败保持原UI和恢复数据；未知不得假成功或假未操作。

picker末级符号链接可由现authorizeSingleFile规范化为canonical实体。建议低成本优先明确确认实际canonical路径：若selectedPath与实体路径不同，额外展示“此入口指向以下实际文件，移入废纸篓的是实际文件，不是链接入口”。不能只显示alias名称却移动实体。若现有可信元数据无法可靠表达二者关系，本片先拒该入口并提示从实际位置选择，不能猜测链接目标；不扩所有祖先链接规则。

无既有OBL直接主责，`none`不表示完整父义务完成。F-028/F-066异常态、F-029授权恢复、阅读子窗、冻结/专项和已有FINAL问题不顺带推进；`F-059a-offline-final`待批准实施时登记，不执行断网。

## 已读真实接点与关键未决

- 本地实际2.0.1 SDK `.hutch/devkit/api/sdks/main/core/Utils.ts` 公开 `moveToTrash(path:string)`；`proc/native.ts`接至 `core_.symbols.moveToTrash(toCString(path))`，公开返回boolean。已读包装层，**未证明内部原生实现、成功含义、错误阶段或对象身份原子保证**；不能把SDK封装使用FFI等同本项目要新增Bun FFI。
- `documents/path-authorization.ts` 与 `workspace/authorization.ts` 可持有父目录/文件descriptor并验证祖先、path/fingerprint及root代数；`documents`的受控broker展示了保存屏障和迟到资格校验，但reveal/default-open不是破坏性操作，不能原样当trash事务。
- 当前Node-API `save-primitives.c`提供open/fstat相关、受限私有暂存发布与排他rename；`removeTemp`只供`.agentic-save-`临时项unlink，不是系统废纸篓，不得借用删除用户文件。现有renameat/renameatx_np仍以名称操作，没有比较expected inode后原子移动的CAS接口。
- `client/documents.protect`、关闭保护、`client/folder-removal`双store prepare/swap/effects及后端单槽收据可借鉴。普通release吞transport异常不能当可见删除成功；既有移除根/独立项只撤窗口引用，不能直接套在trash前。

**当前必要路线问题：路径式trash在最后身份检查之后仍可被其它进程替换。持有fd不等于系统API按该fd操作；系统返回true也不能单凭原路径消失证明进入废纸篓的是原对象。** 后验发现不一致可保守unknown，但无法撤销已经误移动的替代文件；不得将此前检查描述成原子保证。

## 路线候选与建议调查顺序

### A：公开SDK直接路径调用（最轻，但有明确身份空隙）

严格准入/排空已准入save → 短descriptor重验 → 同步调用公开moveToTrash → 记录不可逆阶段收据。独立Standards已核v2.0.1 `nativeWrapper.mm:8264–8277`实际直接fileURLWithPath→trashItemAtURL，返回BOOL但丢弃resultingURL/NSError；并以NSLog输出成功目标URL或含路径错误，**直接调用不符合本项目匿名日志合同，当前不推荐A**。官方NSFileManager.h区分YES成功、NO未移入废纸篓；transport未知仍不能当NO。另有末检后外部名称替换残余风险。总账W-12没有承诺任意外部并发下的inode CAS，不把这一额外强保证设为产品硬门槛，但也不能把本路线描述成已有CAS。

### B：官方macOS对象/URL级接口的窄Node-API桥（先调查，不预写可行）

推荐继续收敛本候选：仅增加窄ObjC Node-API公开平台调用，不输出路径日志，保留系统resultingURL供可信后端核对及固定错误码；不把结果路径直接写日志。官方临时fileReferenceURL能跟随对象路径变化，但部分hierarchy可能无法生成叶对象引用，且不能跨restart/remount持久化；取得引用阶段和与持有fd对应的核验仍须明确。没有已证实的fd/expectedinode条件化trash原子接口，不能将窄桥或“URL而非字符串”伪装为CAS。现Node-API可复用载入/错误编码惯例，不增加通用文件系统框架。以上仅依据主线/独立Standards公开API只读调查，尚未探针或实现。

### C：先移入私有暂存再调用trash（暂不推荐）

可以缩小后段名称被替换机会，但首次rename仍有原名竞态；移错后的后验发现已经改变了用户磁盘。trash失败还需要安全恢复及原路径被占用处理，带来额外可见状态和恢复义务，不是免费安全修复。当前不实施，不自动rmdir/unlink残留，不覆盖恢复。

建议先核A底层公开实现/官方平台合同与B是否确有更强身份语义，再由主线选择最小可靠路线。主线已读取macOS SDK的NSURL.h：fileReferenceURL是对象引用、随路径变化有效，但不跨重启/remount；NSFileManager.h的trash合同区分YES已移动、NO未移动并提供结果URL。上述是官方接口材料，不等于现Electrobun包装已经使用对象引用或证明取得引用的前段没有竞态。调查实际接点后，再冻结明确的本地并发模型、实际保证及剩余风险，不自行新增绝对CAS要求，也不在实施时掩盖已知风险。**本方案尚未选定破坏性调用路线，不批准实际移动探针。**

### 保证与oracle分层

既定产品/安全必达：预检前已替换的目标拒绝；App内部已准入保存、根/授权变更等与磁盘调用互斥；准确区分平台已确认成功、明确失败和回执未知；成功后才接纳UI，失败保原数据；旧操作回执不能撤销新对象/新grant。以上必须实现并验证，不因平台局限放宽。

末检至系统调用之间的外部进程替换属于路线调查必须披露的残余竞态，不是W-12已承诺的绝对CAS。平台对象引用可能缩小风险，但其建立/解析/调用阶段需分别核实；实验oracle须在选路后、运行前冻结真实可达保证。后验unknown只表达证据不充分，不能倒转或“修复”已发生的误移动。

## 共同最小接入合同（路线确认后再typed）

1. renderer仅传opaque目标与root generation/独立handle、操作session/sequence；后端从授权集合解析路径。确认后和磁盘调用前都复核目标、原图与用户意图；save若更换inode必须重获确认后的最新可信证明，不能继续旧fingerprint。
2. 关闭保护/显式确认阶段不先删UI。提交后用专用有界单槽追踪`working / confirmed / failed / unknown`；同operation精确重放只查询，不重复trash。transport丢回执查询原槽；已知副作用之后附带清理异常不倒退成未操作。超时unknown不自动重试破坏性调用。
3. 工作期与保存、授权/根移除、创建及扫描完整批次park形成明确互斥，沿现有document屏障，不另造通用scheduler。成功后同步准备/替换受影响文档与树投影，再通知；保持其它dirty文档/选区/历史。不靠watcher恰好及时到达冒事务完成。
4. 若系统已确认成功而UI接纳失败，保留可查询成功收据和待收敛状态，不假失败再移一次；MRU历史保留，解析自然隐藏不再存在/授权的项。原路径随后出现新对象不能被旧完成回执删除其新节点或撤新grant。
5. unknown提示“结果暂不可确认，请在系统中检查”，保留原编辑缓冲与恢复数据；不能允许盲重创/重复trash，也不能提前清原标签。正常退出沿全部dirty保护处理，具体未知槽释放/退出合同在路线可行后收敛，不沿用创建槽就猜测成立。
