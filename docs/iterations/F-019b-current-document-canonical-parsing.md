## 功能说明与授权

2026-10-02 用户授权按推荐顺序持续推进 MVP，逐功能由 Agent 代验、修复并维护文档；不是用户逐项亲验。用户随后补充每轮自动提交推送授权，Git 由协调 Agent 在本片独立代验后执行。本片从 F-019a 固定语料扩展到当前打开文档的不可变内存正文，尚未提供阅读模式、HTML、资源加载或链接打开。

## 最小技术方案

- 复用已安装 `mdast-util-from-markdown` 的公开 `fromMarkdown` 与 BOM 范围映射，将纯解析与固定语料的 Lezer 对比隔离。
- 按需启动独立 Worker；同时最多一个正在计算的请求。新请求取代旧请求并终止旧 Worker，不建立无限队列。只在调用时解析，不随每键输入自动解析。
- 请求绑定文档身份、内存 revision、原始正文、稳定编辑会话对象和解析配置；控制器变更时立刻使不再匹配的结果失效。generation 防止被终止 Worker 的迟到结果发布；切换、关闭、重新读取及释放消费者均取消。编辑会话标记也区分原文完全相同或空文档的重新读取；单纯选区与模式切换不作内容变化。
- 输出内部 mdast 和计时供后续阅读消费者使用，不形成第三棵结构 AST，不持久化，不建立跨文档缓存。OBL-013 仅当前单消费者取消、限流和版本隔离；多消费者优先级等继续开放。OBL-021 缓存分类、配额和淘汰延后真实阅读消费者。
- 普通 UI 不增加解析摘要；复用 `AGENTIC_MARKDOWN_EDITOR_FAULT_LAB=1` 的显式实验开关，在真实文档工作区提供当前文档解析、取消和状态；不是会替换整个工作区的 PERF_LAB 页面。失败不影响编辑、保存和原文，不记录正文或路径。

## 最小 happy path 与边界验证

1. 打开 Markdown 后请求当前原文解析，确认 CommonMark AST 与原始 UTF-16/BOM/CRLF 范围一致，未保存修改以当前内存为准。
2. 修改正文、切换、重新读取或关闭后，旧结果立即失效；迟到回复不能覆盖新结果。选区变化不改变正文版本。
3. 连续请求、取消、销毁、Worker 错误与不匹配回执不泄漏挂起 promise，不改变文档。
4. 通过真实打包 Worker 与代理 UI 代验，构建及独立复核证据由协调 Agent 补入。自动测试不能伪装成用户亲验。
