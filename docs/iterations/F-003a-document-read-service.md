# F-003a：只读文档服务与跨进程读取

> 状态：已验收（2026-09-20）；2026-09-19 用户确认范围并授权直接推进至人工验收
> 父功能：F-003 Document Service、RPC 与文档身份
> 前置依赖：F-001 已验收；遵守 F-002 持续约束

## 1. 功能说明

### 1.1 目标

在现有应用外壳内验证一条真实、受控的本地文档读取链路：用户选择 Markdown 文件，界面通过后台文档服务取得原文、文档身份与内容版本。此入口用于本轮验收，不是正式阅读模式或打开文档产品交互。

### 1.2 本轮范围

- 在正文占位区提供明确标注的“文档服务验证”入口，调用系统文件选择器，每次选择一个 `.md` 或 `.markdown` 文件；取消选择不改变当前显示。
- 后台读取有效 UTF-8 原文，界面按纯文本只读展示，不解析 Markdown 或 HTML，不执行内容或自动加载资源。
- 展示文件名、`documentId`（逻辑文档身份）和磁盘内容 `revision`（版本），便于人工核对；提供重新读取操作。
- 在本轮应用运行期间，同一未被替换的文件重复读取保留身份；内容未变化保持版本，重新读取发现内容变化时产生新版本。路径与身份分开管理，不拿路径或内容散列直接当文档身份。
- 界面不因较早请求晚返回而被旧内容覆盖；失败有明确提示，不将旧快照标成读取成功的新内容。
- 授权限定为用户在系统选择器中明确选择的文件。界面持有后台签发的只读能力凭据，不通过提交任意路径取得读取权限。

### 1.3 不在本轮范围

不实现正式文件打开入口、文件树、标签、Markdown 渲染、编辑、保存、watcher（文件变化监听）、目录授权、会话恢复或重启后的身份恢复。重新读取前不承诺发现外部变化。

完整路径与卷语义在 F-004 推进，读取保真在 F-010 推进；本轮仍需具备安全读取选中文件的最小校验，不能以这些能力在后续为由暴露任意路径读取。无法可靠判断文件已被替换时应拒绝复用旧授权并要求重新选择，不猜测身份延续。

F-003 中与编辑相关的 buffer revision（未保存编辑版本）、增量传输、重同步及大文本传输评估不在此只读切片中完成。后续必要切片的范围和顺序另行讨论，不提前冻结完整架构。

### 1.4 状态变化

按 F-003a 跟踪本轮；只有本切片实现、真实验证并获人工验收后，才能记为已验收，父功能 F-003 仍不能记为完成。后续依赖方需要哪些已验收能力，应按其当轮范围核对，不能把 F-003a 等同完整 F-003。

## 2. 最小技术方案

- 复用现有 `apps/desktop/src/shared/rpc.ts`、`src/bun/rpc/index.ts` 和 `src/lib/electrobun.ts` 的通信接线；不引入独立守护进程或本地端口。
- 在 Bun 主进程新增职责独立的只读文档服务，系统选择器返回的路径只在后台转换为受控授权。`src/bun/native-files/index.ts` 已有选择器封装，可作为起点，但不是已验收的文档能力。
- RPC（跨进程远程调用）仅暴露选择并授权、凭据读取和释放本轮授权所需的最小操作；增加 TypeScript 类型与运行时校验，拒绝无效协议、畸形参数、伪造或失效凭据，错误不泄漏越权路径或正文。
- 后台维护身份、授权和版本；内容散列辅助判断字节变化，不仅依赖文件修改时间。异步返回携带身份、版本及请求关联信息，界面提交显示前检查其仍对应当前请求。
- 初次读取使用全量快照，不为未实现的编辑链路设计 patch（增量变更）协议。本轮验证入口暂限 1 MiB 原始字节，超限明确失败，不截断；这是临时安全边界，不是最终产品容量或性能门禁。请求仅接受协议版本、至多 80 字符的请求标识与必要的能力凭据，不接受路径或正文。
- 同时只保留一个活动文件的只读授权；成功选择新文件、清空/关闭验证入口或进程退出时释放。取消或选择失败保留原授权。身份与版本的轻量元数据在本次进程中保留，不存正文，重启不恢复。
- 后台持有只读文件描述符，复核普通文件类型、大小、文件对象信号及读取前后状态；检测替换或不稳定读取时拒绝返回，不跟随已授权路径读取新的目标。有效 UTF-8 使用严格解码，BOM 字符保留，不做换行转换。
- 界面只保留当前展示所需快照，不建正文数据库或持久缓存；不记录正文日志。F-002 的离线、非编辑不回写和内容不执行约束随本轮验证。

2026-09-19：用户在确认功能范围后授权直接推进至人工验收。以上最小实现细节在该授权下落实；若需要扩展已确认行为或范围，仍需重新确认。

## 3. 最小 happy path（正常成功路径）

1. 本地准备含中文、标题、链接及 HTML 字面文本的 UTF-8 Markdown 样本，记录原始字节；启动应用。
2. 通过验证入口选择样本，确认纯文本、文件名、身份与版本显示正确；内容不渲染、不打开链接或执行脚本。
3. 再次读取未改变的样本，身份和版本不变。在不替换文件对象的前提下原地修改该测试文件后重新读取，原身份保留，版本更新且显示新内容。编辑器采用原子替换保存的情况按文件替换用例验证，不在本轮猜测身份延续。
4. 再选一个文件，确认身份不同；以可控延迟自动测试旧请求晚返回，确保不能覆盖新选择的结果。
5. 断网后在本地构建中重复选择及读取，操作可用；对未外部修改的样本比较前后字节，确认应用没有写回。

本轮额外验证：取消选择、无效或失效凭据、文件消失/替换、非支持格式及无效 UTF-8 安全失败。上述验证仅覆盖本轮链路，不代替完整 F-004、F-008 或 F-010 验收。

实现后运行受影响代码的格式、类型、lint（静态规则检查）、针对性测试与构建；记录真实命令和结果，不以继承测试替代本轮验证。性能先记录选定样本与读取耗时，不预设通过数值或启动独立大文本评测项目。

### 4.3 人工验收交接

自动 UI 检查最初取得的是仍在运行的旧 F-001 窗口；尝试退出并启动最新版本时，工具报告 Mac 已锁屏，无法继续。没有把旧窗口截图当作 F-003a 已成功运行的证据。真实系统选择器、窗口读取和窗口断网链路均待人工验证。

1. 解锁 Mac，完全退出旧应用后，启动 `apps/desktop/build/canary-macos-arm64/Agentic Markdown-canary.app`。
2. 确认正文区显示“文档服务验证”，选择仓库内 `docs/iterations/fixtures/F-003a-sample.md`，查看中文、星号、链接、HTML 及代码围栏均为原始文字，不渲染或执行。
3. 点击“重新读取”：同一未变文件的 `documentId`、`revision` 保持不变。取消一次新选择，确认显示不变；再选择另一份 Markdown，身份应不同。点击“清空”，确认内容清除。
4. 用测试副本原地修改内容后重新读取，应保留身份并更新版本；若编辑器使用原子替换保存，允许提示重新选择，重选后使用新身份。此文件对象区别也已由自动测试覆盖。
5. 断网后退出并重新启动本地构建，再选择样本并重新读取，确认不依赖开发服务器或网络；顺便回归窗口连续拖动、通高分隔线与 `⌘B`。
