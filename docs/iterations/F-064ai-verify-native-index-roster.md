# F-064ai 核对原生索引正文名册

## 范围

在已有的严格只读重开中，用当次快照核对原生索引实际读取的所有行。清单或代数相符时，仍须核对原生存储中的行 ID、内部路径和正文。普通窗口仍走已有查询。

## 最小实现

1. 复用当前有界传输和 Node-API 桥，在只读原生会话增加无写入的核对操作。接收当次已授权快照的 ID 和正文，最多 16 行、合计 64 KiB 正文字节，允许空名册。
2. 将输入与当前原生会话已加载的全部存活行逐字节比对。保持会话代数，成功不返回原生正文，失配或输入异常不继续查询。
3. 严格重开先完成现有清单预检，再核对原生行，最后查询。沿用取消、租约和结果关闭规则。原生会话会先加载缓存正文，本片验证已加载的数据，不改变缓存权限或擦除语义。

## 最小验收

- 使用实际正式原生资源核对精确同名册、乱序、空名册、边界和无效输入。
- 构造两个同代索引，将不同正文的原生索引配到原清单上。即使当前查询的命中与偏移相同，仍拒绝且不发出查询。成功与拒绝均保留清单、索引及代数。
- 包内复跑，真实 WK 回归原正文搜索、定位和退出。

## 继承约束检查

- F-002 沿用当前授权，离线留最终人工。
- 中文与外观沿用现有搜索面板。
- 命令与键盘沿用现有搜索入口。
- 安全与日志方面，不返回原生正文或路径，不用索引恢复文件授权。
