# 迁出能力承接登记

这是 MVP 规格 6.1 的可追踪明细，不改变产品范围或冻结技术方案。2026-09-21 起新增迭代使用本表；L1 已验收历史文档不补造承接或验收证据。每项仅一个主承接功能；其他功能是协作者，不承担模糊的共同关闭责任。

- 状态：待承接 → 实现中 → 待人工验收 → 已验收。只有用户验收后填写证据并关闭；父功能完成不自动关闭。
- 主承接功能开始时必须在迭代中声明全部所属 ID，并更新本表迭代链接。切片只承接部分时保持父功能未完成；其他项继续待承接，不得静默跳过。
- 本轮实际承接用 `obligations` 标记；剩余同父功能项用 `deferred-obligations` 标记并说明理由和后续切片。机器检查显式承接/延期覆盖，不强迫一个切片实现整个父功能。
- 改派须同步唯一主承接方、相关迭代及文末记录；改变行为或取消需求仍需用户确认。ID 不复用、不删除历史。
- 每轮同时填写继承约束检查：F-002；中文与浅深/系统外观；统一命令/键盘；内容安全与匿名日志。新增 UI 和模块不得因未单列 ID 而免除这些持续要求。
- 若某项没有引入缓存等适用对象，仍需在验收证据说明不适用的事实和用户确认，不以实现空对象来凑完成。
- 运行 `bun run check:obligations` 检查 ID/承接方/状态/证据/迭代引用和真实规格状态。它不能理解语义、判断实现正确性或证明人类确实验收；评审必须核对实际内容。每轮选项介绍与验收关闭前人工核对本表。
