# F-064am 直接正文搜索覆盖扩展到 32 篇

## 范围

普通窗口的直接正文搜索，筛选前合计最多从 16 篇提高到 32 篇。保留最多 16 个根、16 个当前打开文档绑定、16 个独立文件句柄及 64 KiB 正文预算。原生索引继续使用 16 篇和原有字节限制。

## 最小实现

1. 调整独立的直接搜索覆盖数，沿用已拆开的工作区、RPC、客户端和定位预算。界面提示从同一配置取得容量。
2. 筛选前 32 篇和终态第 32 个条目可用，33 篇按原错误整次拒绝。打开及保留命中继续按当次文件身份定位，未保存内容覆盖规则沿用。
3. 进度和终态继续受覆盖数约束。现有字节预算、根与独立句柄、打开绑定和原生索引边界保持现有产品数值。

## 最小验收

- 验证直接工作区恰好 32 篇、逐篇进度、末篇定位和 33 篇筛选前拒绝。原生索引在 17 篇仍拒绝。
- 验证共享协议与客户端覆盖、打开绑定、独立句柄及筛选。已有 64 KiB 字节拒绝仍通过。
- 使用真实 WK 打开隔离 32 篇目录，查询并定位第 32 篇。显示第 33 个隐藏文件后查询拒绝，退出后夹具不变。

## 继承约束检查

- F-002 沿用当前本地授权，离线留最终人工。
- 中文与外观更新搜索容量提示。
- 命令与键盘沿用现有搜索入口。
- 安全与日志方面，容量扩展不改变授权或增加日志。
