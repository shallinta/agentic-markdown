## 继承约束检查

- F-002：只读检测不写入正文、不创建探针文件、不修改权限；本地离线运行。既有未保存内存不因能力变化而丢弃。
- 中文与外观：文件列表、标签与正文提供中文只读或无法确认写入能力的标识；浅深/系统外观可辨识，正文仍能滚动、选择和复制。
- 命令与键盘：统一 capability（操作能力）约束输入、粘贴/剪切/删除、撤销/重做及保存；按钮、命令面板、菜单、快捷键和后端一致。本片不引入拖放、分隔线或文件管理写操作。
- 安全与日志：仅对已授权 handle 检查，不接受调用方路径或自报可写状态；消息严格校验，过期响应不解锁文档；不输出路径、正文或权限探测系统错误。

## 1. 功能说明

1. 打开不可写文件时可查看原文、滚动、选择、复制，但不能修改、撤销/重做正文或保存；展示明确原因。当前只读保护不是阅读模式。
2. 后端综合当前授权、文件与原子替换所需父目录的实际能力生成只读状态。能力无法确认时保守禁写，并区别于已确认的权限只读；不以保存成功承诺替代预检查。
3. 运行中权限变化触发刷新；重新获得焦点或切换文档时也核对，具备有界兜底刷新。权限恢复后无需丢弃内存或历史即可继续；检测不重读正文、不重建 EditorState。
4. 变只读前已有修改完整保留，未保存提示及关闭放弃确认继续有效；不自动重载、关闭、保存或撤销。候选输入期间不通过重建编辑视图丢弃内容。
5. 后端每次实际保存前重新检查；前端禁用不能替代后端拒绝。权限检查与实际写入存在文件系统竞态，最终写入仍以既有原子保存和实际错误处理为准，不声称瞬时变化零延迟或无竞态。

本轮沿用 macOS 普通本地文件、单硬链接和 1 MiB 边界，也沿用 F-015a 对 mode 写位全零的保守拒绝策略，即使 ACL 单独授予写入也不扩展保存支持范围。不新增目录树、重命名/移动/删除、任务框、正式阅读/编辑/源码模式；这些消费者以后必须接入同一只读规则。父 F-016 不随本片完成。

## 2. 最小技术方案

- 新增独立的轻量写入能力协议；由授权服务生成，首次打开随快照返回，后续检查不传正文。未知、失效、检查失败均保守禁写；严格绑定当前授权和文档，丢弃陈旧结果。
- 复用 Node-API 路线，不使用 Bun FFI。使用无截断的文件打开、文件/目录身份及权限检查；macOS flags、只读卷、ACL 检查通过固定原生接口读取元数据，不执行任意符号。文件使用 `faccessat` 的 `_WRITE_OK | _DELETE_OK`、父目录使用 `_WRITE_OK | _EXECUTE_OK`，由系统内核评估 ACL，不实现自制通用 ACL 权限引擎。检查失败时保守禁写。
- 仅对已授权对象进行元数据变更监听，合并刷新；配合焦点/切换核对及有界兜底检查，不递归扫描、不进行全文监听或后台索引。保存后的合法原子替换必须更新检查对象，避免旧文件描述符误判只读。
- controller（文档控制器）与编辑器只读配置共同拦截写事务，保留选择、滚动、历史和原始字节；统一命令复用同一能力。保存仍走已验收的后端安全路径，在实际动作前复核。
- 性能不预设门槛；记录真实验证结果，检查刷新有界、无正文复制与无每键 RPC。

## 3. 最小 happy path 与边界验证

1. 一次性可写/只读文件分别打开：只读标识正确；只读可选择复制但键入、粘贴、删除、历史及保存不改正文或磁盘；可写文档编辑保存正常。
2. 运行中修改一次性样本的文件和父目录权限，再恢复：能力自动变化；保留未保存内容、选区和历史。不操作用户真实文件权限。
3. 强行调用保存 RPC 不能绕过只读；拒绝伪造/过期 handle 及响应；保存成功后后续检查与再次保存正常，不被旧 inode 干扰。
4. 组合输入保护、保存状态与关闭确认回归；原文 BOM/混合换行不变。自动测试不能替代真实输入法实测。
5. 运行相关与全量测试、类型、Lint、格式、文档/承接检查，独立审查；构建前版本从 alpha.12 递增，核对产物，实际窗口验证后交人工验收。
